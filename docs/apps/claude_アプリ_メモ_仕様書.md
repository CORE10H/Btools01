# アプリ：メモ（`apps/memo.html`）仕様書

## 概要

プロンプトギャラリー（`アプリ_プロンプトギャラリー_仕様書.md`）を土台に実装した、複数メモをカード一覧管理するアプリ。

## データ構造（1件あたり）

タイトル／本文／タグ（複数）。画像は扱わない（テキスト専用）。

## 保存先

IndexedDB（DB名`sideops_memo`）。`entries`ストア（メモ本体）と`settings`ストア（よく使うタグ・タグの色設定）の2ストア構成。プロンプトギャラリーとは別DBのため相互に影響しない。

## 一覧表示

カード＝1件。タイトル（未入力時は本文冒頭を自動使用）・本文抜粋（4行でクリップ）・更新日時・タグピルを表示。

## 並び順（2026-10-10〜）

ヘッダーの選択欄（`#sortSelect`）で選ぶ。6通り：更新が新しい順（既定。以前からの並び）・更新が古い順・作成が新しい順・作成が古い順・タイトル順・タイトル逆順。

- タイトル順は、カードに出ているタイトル（未入力なら本文の冒頭）で比べる。`Intl.Collator('ja', { numeric: true })` で、数字は数として比べる（メモ2 → メモ10）
- 同じ値どうしは、更新が新しい順、それでも同じならidの順（並びが理由もなく入れ替わらないように）
- 検索・タグの絞り込みと一緒に効く。並べるのは描画のたび（`renderGrid`）なので、書いたメモは閉じたときに正しい位置へ移る（以前は再読み込みまで元の位置のままだった）
- 選んだ順は端末ごとに覚える（`localStorage`の`sideops_memo_sort`）。同期されるDB（`settings`ストア）には入れない（端末ごとの好みのため）。覚えている値が6通りのどれでもないとき・`localStorage`が使えないときは「更新が新しい順」
- メモのデータの形は変えていない（`SYNC_APP_BUILD`は上げていない）

## キー操作（2026-10-10〜）

| キー | 場所 | 動き |
|---|---|---|
| `Esc` | メモを開いているとき | 保存してから閉じ、一覧へ戻る（✕と同じ） |
| `Esc` | そのほか | 削除の確認・よく使うタグ・タグの色・「+n」の画面・☰メニューを閉じる |
| `Enter` | タグの入力欄 | タグを足す |
| `Enter` | 「よく使うタグ」の入力欄 | よく使うタグに足す |
| `Tab` / `Shift+Tab` | メモを開いているとき | 下の順に回る（逆回り） |
| `Enter`・`Space` | ✕にいるとき | 閉じて一覧へ戻る |

Tabの順：タイトル → タグの✕（付いている数だけ）→ タグの入力欄 → よく使うタグ → 本文 → ✕（一覧へ戻る）→ タイトル → …（循環）

- 以前は本文の次が「このメモを削除」で、その先はメモの外（後ろに隠れている一覧の検索欄など）へ抜けていた
- 「このメモを削除」は`tabindex="-1"`でTabでは止まらない（本文の次で押し間違えないように）。クリック・タップでは押せる
- ✕にいるときは枠（`:focus-visible`）で分かるようにした。ツールチップは「一覧へ戻る（Esc）」
- 歯止め：それでもメモの外へフォーカスが行ったら（`focusin`）、タイトルに戻す。削除の確認を出している間は何もしない
- 歯止め：日本語の変換中のキー（`isComposing`、または`keyCode` 229）は扱わない。変換を`Esc`で取り消したときにメモを閉じない、変換を確定する`Enter`で変換前の文字がタグにならない、MS-IMEが変換中の`Tab`で予測候補を選ぶのを邪魔しない
- 確認：`D:\dev\sideops_sync_verify\memo_e2e.dart`（並び順・Tab・変換中のキー。一時メモの確認も同じファイル）

## ヘッダー

`// MEMO`・検索欄・タグの絞り込みチップ・並び順・「＋ 新規メモ」・☰ を1段に並べる。幅640px以下（スマホの縦向きなど）では2段にする（2026-10-06〜。以前は検索欄が「＋ 新規メモ」に重なっていた）：1段目＝タイトル・並び順・「＋ 新規メモ」・☰、2段目＝検索欄とタグ。作りはPROMPTGALLERYと同じ（`アプリ_プロンプトギャラリー_仕様書.md`「ヘッダー」）。画面の幅が変わったら（回転など）タグを並べ直す。

## 保存方式（自動保存・保存ボタンなし）

入力停止から600ms後にデバウンス保存。以下の誤作動防止策を組み込んでいる：

- 保存処理をPromiseチェーンで直列化し、連続入力による多重実行を防止
- タイトル・本文・タグすべて空のままエディタを閉じた場合、DBにゴミデータを残さず自動削除
- エディタを閉じる操作（✕・Esc・外側クリック）の際は、デバウンス待機中の変更を即座にflushしてから閉じる（変更の取りこぼし防止）
- 保存待ち中にページ離脱しようとした場合、`beforeunload`でブラウザ標準の確認ダイアログを表示

## タグ機能・選択削除モード

プロンプトギャラリーのロジックをそのまま流用（よく使うタグ・タグの色・絞り込み・検索・選択削除モード）。単一メモ内で複数タグを扱える、「複数メモをリスト管理」構造。

タグ絞り込みチップの「+n」方式・二重スクロールバー対策（`アプリ_プロンプトギャラリー_仕様書.md`参照）も同じ内容で実装済み。

## 削除確認

自動保存には「元に戻す」がないため、削除操作のみ確認ダイアログを必ず経由する。

## モーダルの開閉方式（重要な実装ルール）

モーダルを新設・改修する際は、`classList.add('is-open')`方式とHTML側のインライン`display:none`を絶対に混在させないこと。インラインでdisplay:noneを固定すると、CSSクラス側の`display:flex`が詳細度で負けて開かなくなる。新設するオーバーレイは、インラインstyleで開閉に関わるプロパティを指定せず、CSSクラス（基本形の非表示＋`.is-open`での表示）だけで完結させる。

（過去にこのアプリ固有で、「よく使うタグ」「タグの色」モーダルがインラインの`display:none`により一度も開けない不具合が発生し、修正済み。同じ日に新設した「タグで絞り込み」モーダルも`style.display`直接操作方式から`classList`方式に統一した。）
