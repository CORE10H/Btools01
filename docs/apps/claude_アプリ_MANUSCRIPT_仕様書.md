# アプリ：MANUSCRIPT（`apps/manuscript.html`）AI執筆特化の小説制作アプリ 仕様書

## 概要

旧来の小説執筆アプリ「manuscript」の簡易版として、AIでの作成に特化させた先天的アプリ（`builtin`）。ネタ帳を書き溜め、ネタから設定プロット、設定プロットから画像生成プロンプトと作品紹介、そして本文を作り、推敲・公開した完成品を「本」として本棚に保管する。小説だけでなくPV・ショート動画などのビジュアル展開に使う画像（表紙・カバー・章の画像・設定画像）と、その画像生成プロンプトも作品と一緒に保持する。

**生成そのものはアプリの外（外部AI）で行う。** アプリが担うのは「テンプレートに素材を差し込んでプロンプトを作る → 外部AIの出力を貼り戻す → 保存する」だけで、API・APIキーは持たない（SCRIBITと同じ方式。API連携は利用者側の負担も増えるため保留）。

### 想定している導線（2026-10-12〜。ユーザーの使い方に合わせて組み直した）

1. ネタ帳からネタを選ぶ（ネタの画面の「このネタで作品を作る」、または作品の「1 元になるネタ」）
2. 「2 設定プロット」でテンプレートと合わせてプロンプトを作る → AIで設定とプロットを作る → 貼り付ける
3. 「3 素材をまとめて作る」でプロンプトを作る → AIで「登場人物の画像生成プロンプト・キービジュアルの画像生成プロンプト・各章のタイトル画像の生成プロンプト・作品紹介」を一度に作る → 「AIの出力を貼り付けて振り分ける」に貼ると、見出しごとに各欄へ振り分けられる（人物・章がなければ作る）
4. 「7 本文を通しで頼む」でプロンプトを作る → AIに1回だけ貼り、「次の章もお願い」で1章ずつ本文を書いてもらう
5. 出来上がった本文を、章のタブを選んで「8 完成稿」に1章ずつ貼る（編集・推敲もここで）

それまでは「章ごとに本文のプロンプトを作り直し、前の章の要約（7 要約）で引き継ぐ」作りだった。章ごとの「本文」の段はなくし、要約は予備としてたたんで残している（AIのべりすと等で使うかもしれないため）。

- ランチャー表示名：`MANUSCRIPT`（`BUILTIN_APP_CHOICES`、カバー画像は`apps/img/manuscript.jpg`）
- テーマ追従：`<head>`で`sideops-theme-bridge.js`を読み込み、色はすべてCSS変数で記述
- 本文・閲覧画面のみ明朝体（Shippori Mincho）、それ以外は他アプリ共通のIBM Plex Sans JP

### 作品エディタの構成（2026-10-12〜。2026-11-07 から工程タブ）

作品の顔（表紙・題名・名義・次にやること）の下に、4つの工程タブ（**01 設計**＝1・2／**02 素材**＝3〜6／**03 本文**＝7と章の8〜11／**04 仕上げ**＝本棚・書き出し）。1画面に出すのは選んだタブの中身だけ（「見た目：作品エディタの見出しの段差」の3段目）。工程の番号 1〜11 はそのまま（トーストや説明の「③ で入ります」「⑧ 本文」が通じるように）。画面の文で工程を指すときは、2026-11-07 から丸数字（①〜⑪）で書く（「微調整（2026-11-07）」）。

**作品の土台**（作品に1つ。01 設計・02 素材）
1. 元になるネタ（複数可）。マウスを重ねると、そのネタの全文が浮かぶ（2026-11-07〜。見るだけ）
2. 設定とプロット（作品全体の設計図。AIの出力をまとめて貼る。2026-11-07 に「設定プロット」から名前を変えた）
3. 素材をまとめて作る：用途「素材」のテンプレートでプロンプトを作り、AIの出力を「AIの出力を貼り付けて振り分ける」に貼る（「素材の振り分け」）
4. 設定集（人物・場所・施設・アイテム・用語・その他。1項目ごとに名前・説明・**画像生成プロンプト**・画像1枚）。画像のない項目でもプロンプトがあれば、カードに「（プロンプトあり）」と出す。項目の画面の頭は2列（左に設定画像、右にカテゴリ・名称・説明。2026-11-07〜）
5. 作品ビジュアル：**キービジュアルの画像生成プロンプト**、表紙（縦3:4、本棚用）とカバー（横16:9、PV・動画用）。AI連携の行の「プロンプトを作る」（用途「作品ビジュアル」）も残している
6. 作品の概要（2026-10-10〜）：作品の宣伝・紹介に使う文章。3 の【作品紹介】もここに入る。プロンプトの合成、貼り付け・直接編集、文字数、1世代退避、「概要をコピー」。`{{概要}}`でほかのテンプレートにも差し込める。閲覧の画面ではタイトルの下に出す

**章**（03 本文。章の一覧で切り替え。追加は一覧の「＋ 章を追加」、並べ替え・削除は章の見出しの右の歯車（2026-11-07〜）。最後の1章は削除不可。PCでは左に章の一覧・右にその章、スマホでは横にすべるタブ）

7. 本文を用意する（2026-11-07 に「本文を通しで頼む」から名前を変えた。作品に1回。章の一覧より上）：用途「通しの本文」のテンプレートでプロンプトを作る。`{{章の一覧}}`で章の一覧を差し込む
8. 本文（2026-10-17 に「完成稿（本文）」から名前を変えた。データの項目名は`final`のまま）：AIが書いたその章の本文を貼る。編集・推敲もここで行う（「AIに推敲を依頼する」の行の「プロンプトを作る」は本文を差し込む）。見出しの右に「推敲中／完成」の切り替え、項目名の右に「本文をコピー」（下の「本文の推敲中／完成・コピー」）
9. 章の画像：**この章のタイトル画像の生成プロンプト**（③ で入る）、AI連携の行の「プロンプトを作る」、画像（横16:9）
10. この章の公開（URL・公開日。note記事IDを自動記録。章単位の.md書き出し）
11. この章の要約（予備）：今の流れでは使わない。はじめからたたんである（`{{前章まで}}`に使われる）

- 番号の移り変わり：2026-10-10 に「作品の概要」を土台の5番目に足し（章は6〜10）、2026-10-12 に「素材」「通しの本文」を足して「本文」の段をなくした（土台1〜6・章7〜11）。案内のトーストの番号も合わせてある
- **以前の本文（初稿）**：章ごとの「本文」の段（`chapters.body`・`outline`）は画面からなくした。以前のデータで本文か章の筋が残っている章だけ、完成稿の上に点線の枠「以前の本文（初稿）」を出す（「本文を完成稿に写す」「以前の本文と章の筋を消す」。消すときは確認。完成稿が空なら先に写すよう確認文で促す）。章を開いたときに出すかを決める（消している途中で欄が消えないように）。データは消さないので、何もしなければそのまま残る

**仕上げ**（04 仕上げ）：出す前の点検・作品の数字（2026-11-08〜。「04 仕上げ：出す前の点検・作品の数字」）、本棚登録、全章の完成稿を.mdで書き出し、作品のJSONエクスポート。作品の削除は 2026-11-07 から ☰ の「この作品を削除」（「作品の削除」）

作品の顔（2026-11-07〜。それまではタイトルの右）に「検索・置換」（2026-10-13〜。「この作品の中を検索・置換」）。入力欄の [ ] と 〔〔 〕〕 は色で強調する（「注釈の強調」）。

### たたむ（2026-10-10〜。2026-11-07 から「11 要約」だけ）

「11 この章の要約（予備）」の段の見出しは、押すとたたむ／開く（`<button>`。`aria-expanded`・Enterキーでも操作できる）。2026-11-07 までは「作品の土台」「章」「本棚・書き出し」の3つの大きい見出しもたためたが、工程タブに置き換えてなくした（以前に覚えた base・chapter・book の値は「知らない見出し」として読み飛ばす。消さなくてよい）。

- たたんだかどうかは**作品ごとではなく端末ごと**に覚える（`localStorage`の`sideops_manuscript_fold`。同期しない）。覚えるのは既定と違う値だけ（例：`{"base":true}`、要約を開いたら`{"summary":false}`）。既定は「要約だけたたむ・ほかは開く」。使えない環境・壊れた値では既定で始める。真偽値以外の値と知らない見出しは無視する
- （2026-11-07 まで）大きい見出しには中身の進み具合を出し、新しい作品ではたたんであった「作品の土台」を開き、素材が空のトーストには「（「作品の土台」はたたんであります…）」と付けていた。今は工程タブの札が進み具合を出し、新しい作品は「01 設計」で開き、トーストはその欄が今と別のタブにあるときだけ「（「01 設計」のタブにあります）」と付ける
- たたんでも入力欄は残っているので、保存・プロンプトの合成には影響しない

名義（ペンネーム）とシリーズは作品ごとに持ち、入力欄は既存の値を候補表示する（表記ゆれ防止）。

画面では、章の本文（`final`）を 2026-10-17 から「完成稿」ではなく「本文」と呼ぶ（書き出し・本棚・確認文・検索の欄の名前・トーストもすべて）。この仕様書で「完成稿」と書いてある所は`final`（＝画面の「8 本文」）のこと。\n\n作品の段階はデータから自動判定する（2026-10-12〜）：すべての章に完成稿あり→推敲、完成稿（または以前の初稿）のある章あり→執筆、プロットあり→プロット、それ以外→構想。本棚登録だけは明示フラグ（`isBook`）。それまでは「完成稿のある章が1つでもあれば推敲」だったが、完成稿に1章ずつ貼る流れでは1章目で推敲になってしまうため変えた。

## データ構造（IndexedDB・DB名`sideops_manuscript`・DB version 3、すべて`keyPath: 'id'`）

```
genres    { id, name, note, order, createdAt, updatedAt }
neta      { id, body, tags[], genreId('' = 未分類), createdAt, updatedAt }   // タイトルは 2026-10-10 になくした
works     { id, title, penName, series, netaIds[], plot, synopsis, kvPrompt, tpl{用途:テンプレートID}, isBook, bookAt, undo{plot,synopsis,kvPrompt}, createdAt, updatedAt }
chapters  { id, workId, order, title, outline, body, summary, final, imgPrompt, done, publishUrl, noteId, publishedAt, undo{body,summary,final,imgPrompt}, createdAt, updatedAt }
lore      { id, workId, kind(person|place|item|term|other), name, body, imgPrompt, undo{imgPrompt}, createdAt, updatedAt }
images    { id(<所有者ID>:<枠>), ownerId, workId, genreId, slot(kv|cover|img), blob, type, name, w, h, updatedAt }
templates { id, kind, name, body, createdAt, updatedAt }
meta      { id, value }   // lastFullExportAt（最後に全件エクスポートした日時）
```

- 画像はBlobのまま保存。枠は「作品の表紙`<作品ID>:kv`」「作品のカバー`<作品ID>:cover`」「章の画像`<章ID>:img`」「設定画像`<設定ID>:img`」「ジャンルの表紙`<ジャンルID>:cover`」。作品に属する画像は`workId`、ジャンルの表紙は`genreId`を持ち、削除・エクスポート時に一括で扱えるようにしている
- ネタは1つのジャンルにだけ属する（フォルダ方式）。存在しないジャンルを指すネタは読み込み時に未分類として扱う
- **ネタにタイトルはない（2026-10-10〜）**。それまでは任意の`title`を持てたが、使っていなかったのでなくした。以前のデータ・以前の形のJSONにタイトルがあれば、読み込み時に本文の1行目へ移す（本文が空ならタイトルが本文に、本文の1行目がタイトルと同じなら足さない）。DBの中でタイトルを持っていたネタだけを、移した形で書き直す（更新日時は変えない。どの端末で書き直しても同じ中身になり、同期で競合にならない。タイトルが空・ないネタは書き直さない）。項目を変えたので`SYNC_APP_BUILD`を`2026101003`に上げた
- ネタを短く示すところ（作品エディタの「追加するネタ」の選択肢・削除の確認文）は本文の1行目（40字まで）を使う。`{{ネタ}}`には「## ネタ1」「## ネタ2」…で区切って本文とタグを入れる
- 作成したプロンプト自体は保存しない（テンプレートと素材から毎回作り直せるため）。AIが書いた画像生成プロンプト（`kvPrompt`・`imgPrompt`）は「AIの出力」なので保存する
- v1（章のない形式。作品に本文・完成稿を直接持つ）のデータは、読み込み時・インポート時に第1章へ自動移行する
- `works.synopsis`（作品の概要。10万字まで）は 2026-10-10 に足した項目。持っていない以前のデータは空の概要として読む（DBの版は3のまま。項目を足したので同期の`SYNC_APP_BUILD`を`2026101002`に上げた）
- `works.kvPrompt`（キービジュアルの画像生成プロンプト）・`chapters.imgPrompt`（章のタイトル画像の生成プロンプト）・`lore.imgPrompt`（設定集の項目の画像生成プロンプト）・`lore.undo` は 2026-10-12 に足した項目（各10万字まで。ない以前のデータは空として読む）。`works.tpl`は画面に出さない用途（章ごとの本文）の選択も持ち運ぶ。`SYNC_APP_BUILD`を`2026101201`に上げた
- `chapters.body`・`outline` は 2026-10-12 から画面で使わない（以前のデータのために残す。上の「以前の本文（初稿）」）
- `chapters.done`（その章を「完成」にしたか。真偽値。ない以前のデータは「推敲中」）は 2026-10-17 に足した項目。`SYNC_APP_BUILD`を`2026101701`に上げた

## ID方式（重要）

形式：`<接頭辞>_YYYYMMDD_HHMMSS_<英数小文字4桁>`（例：`ms_20260929_153045_a7k2`）

| 接頭辞 | 対象 |
|---|---|
| `nt_` | ネタ |
| `ms_` | 作品 |
| `ch_` | 章 |
| `lr_` | 設定集の項目 |
| `tp_` | テンプレート |
| `gn_` | ジャンル |

- **作成時に1回だけ発行し、エクスポート・インポートを含むどの経路でも変更しない**（例外はインポートで「複製」を選んだときの新規発行のみ）。UIからも編集不可（作品IDはクリックでコピーのみ）
- 末尾4桁は`crypto.getRandomValues`による乱数。既存IDと衝突した場合は再発行する
- 例外：あとから足した用途の初期テンプレートだけは、IDと日時を固定にしている（「作品の概要」`tp_20261010_000000_syn1`＝2026-10-10 0:00、「素材」`tp_20261012_000000_ast1`・「通しの本文」`tp_20261012_000000_ser1`＝2026-10-12 0:00、いずれも日本時間）。すでに使っている端末が順に新しい版を開くと、それぞれで初期テンプレートができるため、乱数のIDだと同期で同じテンプレートが2つになる。固定にしておけば中身がまったく同じになり、同期は1つにまとめる（`js/sync.js`は中身が同じなら競合にしない）
- 参照（作品→ネタ・テンプレート、章・設定→作品、画像→所有者）はすべてIDで持ち、タイトルでの照合は一切しない（素材の振り分けで人物を名前で探すのは、AIの出力を入れる先を決めるときだけ）

旧manuscriptで「GitHub保存した作品とJSONエクスポートした同一作品が別作品扱いになる」問題の対策として採用。旧manuscriptとの互換は対象外（持ち越し）。

## テンプレートと差し込み

| 設定画像（画像を頼む） | `{{設定項目}}` | 設定集の項目 | 名前か説明 |
| 作品ビジュアル（画像を頼む） | `{{プロット}}` | 土台5 | 設定プロット |
| 作品の概要（2026-10-10〜） | `{{プロット}}` | 土台6 | 設定プロット |
| 本文を通しで頼む（2026-10-12〜） | `{{プロット}}` | 章7 | 設定プロット |
| 推敲 | `{{本文}}` | 章8 | その章の本文 |
| 章の画像（挿絵を頼む） | `{{本文}}` | 章9 | その章の本文 |
| 章の要約（予備） | `{{本文}}` | 章11 | その章の本文 |
