# ダッシュボードパネル群 仕様書

対象：INTEL（現況）・タスク/ToDo・LOG（通知）・TIMELINE（スケジュール）の4パネル。

## 画面構成（現行レイアウト・PC版）

PC全画面前提、`100vh / 100vw` 固定の CSS Grid（`.shell`）。スクロール無し。

```
┌─────────────────────────────────────────────┐
│ HEADER（左：ロゴ+日付+時計／右：全画面・クラウド・設定アイコン）│
├───────────┬─────────────────────┬───────────┤
│           │                     │  INTEL(1列3行)│
│ カバーフロー│                     ├───────────┤
│（縦・循環） │      STAGE          │  LOG       │
├───────────┤  （バナークリックで展開）│           │
│ タスク     │                     │           │
│           ├─────────────────────┤           │
│           │ TIMELINE            │           │
└───────────┴─────────────────────┴───────────┘
```

- 左カラム・右カラムは`perspective` + `rotateY`で3D傾斜（詳細は`3D変形とスタッキングコンテキスト_仕様書.md`）
- ヘッダー右端はStage右端とピクセル単位で一致（`grid-template-areas`で`header`を`left`+`stage`列のみに限定）

## パネル名称について（旧称との対応）

各パネルの実態が当初の名称と乖離したため、表示名だけでなくCSSクラス名・ID・JS変数/関数名・IndexedDB名まで含めて内部識別子を統一済み。旧称は使用しない。

| 現在の名称 | 旧称 | 用途 |
|---|---|---|
| INTEL | KPI | 読者一覧・記事別スキ数リストなど人物・作品データの集約置き場 |
| LOG | 通知 | 達成ログ・公開ログのような一時的なイベント記録 |
| TIMELINE | ガント | 直近3日〜1週間の行動別の時間配分の可視化（予定・進捗管理ではない） |

現在のCSSクラス：`.intel-card` / `.intel-*`（grid-area `right-intel`）、`log*`（JS変数/関数）、`LOG_*`（JS定数）、`.timeline-panel`（grid-area `timeline`）。IndexedDB名は`sideops_log`。タスクパネル（`task-panel-left`）は改称対象外（元から統一済み）。

## INTEL（現況、1列3行）

1. **売上**：今月の総売上（前月比）＋ドーナツグラフ（プロジェクト別比率）＋凡例
2. **稼働時間**：今月の総稼働時間（前月比）＋ドーナツグラフ＋凡例
3. **コスト/純利益**：今月の総コスト・純利益を横並び表示

ドーナツグラフはSVGの`stroke-dasharray`/`stroke-dashoffset`による自前実装（外部ライブラリ不使用）。表示面（4枠）は静的ダミー値。内部データ構造の設計は`note連携_仕様書.md`を参照。

## タスク/ToDo

カバーフロー直下、固定高さ（220px）。フィルタ（すべて／締切間近／完了）、チェックで完了トグル（見た目のみ、永続化なし）。締切間近のタスクは1.6秒周期でラベルが点滅する演出付き。

データ本体は別アプリ「DONE MORE」（`apps/done-more.html`）側のDBに一本化する方針。タスクパネル自体は完了チェックのみできる簡易プレビューとする設計だが、DONE MOREとのデータ連携は未実装（詳細は`アプリ_DONE-MORE_仕様書.md`参照）。

## LOG（通知）

右カラム下部、残りスペースを`flex:1`で埋める。スクロールバーは出さず、`overflow:hidden`＋下端フェードアウト演出。各通知テキストは1行`text-overflow: ellipsis`で省略。

### 外部メール連携（ポーリング方式）

静的HTML/JS単体ではプッシュ通知（OS通知等）が不可能なため、「数分おきに取得元URLをfetchして新着があれば反映する」ポーリングのみで実装。取得元URLはアプリにハードコードせず、設定モーダルの「通知の取得元」欄でユーザー自身が入力する汎用ポーリング機構（IFTTT・Zapier・Google Apps Script等、どのサービスを使うかはユーザーの自由。本体コードは特定サービスに依存しない）。

- データはIndexedDB（`sideops_log`、`items`/`settings`の2ストア）に永続化
- 期待するJSON形式：`{ "notifications": [{ "id", "title", "body"(任意), "timestamp", "url"(任意) }, ...] }`
- 取得間隔は1〜30分の範囲でユーザーが選択可（下限・上限にクランプ）
- 空状態は「URL未設定（設定から取得元を登録してください）」と「新着なし（新着はありません）」を文言で区別
- フールプルーフ：URL未設定時は起動しない、fetch失敗時は前回表示を維持、エントリごとのバリデーション、id重複排除、保持件数50件で自動間引き、非表示タブでのポーリング停止、`textContent`のみでXSS対策（詳細な定型パターンは`IndexedDB実装パターン_仕様書.md`参照）
- 通知データに`source`フィールド（現状`'external'`固定）を保持。将来的なアプリ内部イベント通知（売上◯◯突破 等）への拡張余地はあるが、検知ロジック自体は未実装

プッシュ通知（OS通知等）は静的HTML/JS単体では実現不可能なため対応しない方針で確定（常時稼働のサーバー・Service Worker等が別途必要なため）。

## TIMELINE（スケジュール）

Stage直下、幅をStageに合わせる。プロジェクト別の「執筆」「推敲」「配信中」などのタイムラインバー（-24H〜NOWの相対時間軸）。

## アンビエントアニメーション（背景の演出）

常時ループではなく、ランダムな間隔で発火する2種類の演出：

- **パネルボーダービーム**：4〜9秒間隔で、ランダムに選ばれた1つのパネルの枠線が一瞬cyanに発光
- **INTELグリッチ**：4〜10秒間隔で、INTELパネルのドーナツグラフいずれか1つにRGBずれ風のグリッチが0.28秒だけ発生

いずれも`prefers-reduced-motion`設定時は完全に無効化される。
