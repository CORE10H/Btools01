# ヘッダーの操作アイコン・設定モーダル 仕様書

## ヘッダーのアイコンボタン

ヘッダー右端に3つのアイコンボタンを配置：

- **⛶ 全画面表示**：Fullscreen APIで全画面のON/OFF切替。全画面中はcyanでハイライト。全画面をやめるのはこのボタンだけ（Androidの「戻る」で解けたときは、次のタップで全画面に戻す。下記「全画面表示と「戻る」」）。ホーム画面に追加したSIDE-OPSでは隠す
- **☁ 同期**：同期モーダル（`#syncOverlay`）を開く（2026-10-05〜）。クラウド（OneDrive・Googleドライブ）につないでいる端末では、開いたときにそのまま同期を始める。ボタンの右上に状態の印（cyan：同期している／amber：ログインが必要・未送信の変更がある・3日以上同期していない／magenta：前回失敗／点滅：同期中）。2026-10-06からは、ヘッダーのすぐ下に同期の帯（`#syncBanner`。自動の同期の進み具合・結果・未送信・失敗）と、画面の中央に同期の状態のモーダル（`#syncProgress`。手動の同期の進み具合・結果・開いたときのログイン切れの確認）を出す。ボタンはHTML上では無効で、`js/sync.js`が読み込まれたときだけ有効になる。詳細は`planning/claude_クラウド同期_仕様書.md`の「段階1の実装」「段階2の実装」
- **⚙ 設定**：クリックで設定モーダルを開く

### 全画面ツールチップの注意書き

ボタンをクリックして入った全画面はJSのFullscreen APIで管理され、同じボタンで解除もできる。ただしブラウザのF11キーで入った全画面はJSから検知できない（ブラウザネイティブの機能のため）ため、その場合はEscキーでのみ解除可能。ツールチップに「このボタン推奨。F11で入った場合、解除はEscキーのみ対応」と明記している。これはブラウザのセキュリティ仕様上の制約であり、コード側での完全な解消はできない。

### 全画面表示と「戻る」（2026-10-06）

**ブラウザの決まり（変えられない）**：Androidのブラウザ（Chrome・Braveなど）では、全画面表示（Fullscreen API）の間にスマホの「戻る」を押すと、ブラウザがそれを全画面の解除に使ってしまい、ページには戻る操作が届かない。ページの側から止める方法はない。また、全画面にするにはユーザーのタップが要る（タップなしでは全画面に戻せない）。

そのうえで、「全画面は⛶ボタンでしかやめない。戻るはモーダル・Stageを閉じるだけ」に近づけるため、2つの方法を用意した。

**① ブラウザのままで使うとき（`js/main.js`）**：タッチ操作の端末（`pointer: coarse`）で、⛶ボタン以外の理由で全画面が解けたときは

1. それを戻る操作とみなして、いちばん上に開いているもの（本体のモーダル → アプリのモーダル → Stage）を1つ閉じる（`SideOpsBackNav.backOne()`。`claude_メインステージ_仕様書.md`「戻る操作」）
2. 画面の上に「画面をタップすると全画面に戻ります」（`.fs-restore`）を出し、次のタップで全画面に戻す。そのタップは全画面に戻すだけに使う（下のボタン等は押されない）。案内の「全画面をやめる」を押すと、全画面に戻さずに案内を消す

| 歯止め | 内容 |
|---|---|
| ⛶ボタンでやめたとき | 戻る操作とみなさない。案内も出さない（`fsWanted`を下ろしてから解除する） |
| PC（マウス） | Escなどで解いたときは、自分でやめたものとして扱う（戻る操作とみなさない・案内も出さない） |
| 画面が隠れたとき | 解ける前後1秒以内に画面が隠れた（別のアプリへ切り替えた・画像を選ぶ画面が開いた等）ときは、戻る操作とみなさない。案内は出す（戻ってきたらタップで全画面に戻せる） |
| 画像などを選ぶ画面 | 本体の`input[type=file]`のクリック、またはアプリからの知らせ（`sideops:picker`。`apps/sideops-theme-bridge.js`が送る）から60秒の間は、戻る操作とみなさない。選ぶ画面を開くと全画面が解ける端末があり、そのとき入力中のモーダルを閉じてしまわないように |
| 待ってから判断 | 解けてから350ms待ち、その間に全画面に戻っていたら何もしない |

**② ホーム画面に追加して使うとき（PWA、`manifest.webmanifest`）**：`display: fullscreen`のアプリとして開く。もともと全画面で（Fullscreen APIを使わない）、戻る操作は普通にページに届くので、戻るでモーダル・Stageが閉じ、全画面は解けない。このときは⛶ボタンは要らないので隠す（開いた時点で`display-mode: fullscreen`かつタッチ操作の端末）。

- 追加のしかた：Brave・Chromeのメニュー →「ホーム画面に追加」または「アプリをインストール」
- アイコンは`icons/`（192px・512px・マスク用512px・iPhone用180px）。`D:\dev\sideops_sync_verify\icons.dart`で描いて書き出したもの
- Service Workerは使っていない（今のChrome系はなくてもインストールできる。オフライン用のキャッシュは、古い版が残る原因になるので入れない）
- 範囲（`scope`）と開始位置（`start_url`）は`./`＝`https://core10h.github.io/Btools01/`。OneDriveのログインの戻り先と同じなので、ログインもアプリの中で完結する（はず。実機で要確認）
- ホーム画面のSIDE-OPSとブラウザのタブのSIDE-OPSは、同じ保存場所（IndexedDB）を使う（同じブラウザの場合）

## 設定モーダルの構成

- **壁紙**：プリセット4種（なし／ネビュラ／オーロラ／マゼンタ靄、すべてインラインSVGグラデーションで外部依存なし）＋カスタム画像アップロード（アップロードした画像はスウォッチとして追加され、再選択可能）
- **透過率**：INTEL・タスク・LOG・TIMELINEの背景のみを透過（文字は不透明のまま）。カバーフローとStageは対象外の固定仕様
- **テーマ**：ダーク／ライト／ビビッド／高コントラストの4プリセットをワンクリック切替。加えて💧スポイトボタンで、設定中の壁紙画像から自動でテーマカラーを生成可能（壁紙未設定時はボタン自体が無効化）
- **カスタムテーマ編集**：テーマ行のプリセット4種とスポイトの間にある画像アイコン（`customThemeBtn`）から、専用モーダルで色を1色ずつ調整できる（詳細は「色の設計」節を参照）
- **アプリ管理**：後天的アプリ（imported）本体の削除画面への導線（詳細は`アプリランチャー_仕様書.md`参照）

3D傾斜角度は50度に固定（可変UIは無し）。

## カスタムテーマ編集モーダル

- 初期値は、保存済みのカスタムテーマがあればそれ、なければ今選ばれているテーマの色をコピー
- 各色にカラーピッカーとHEX入力を用意し、触るたびに画面全体へリアルタイム反映（プリセットの選択表示を崩さないよう、`applyTheme()`ではなくCSS変数を直接書き換える）
- `--panel-rgb`だけは「R, G, B」形式でHEXではないため、カラーピッカー用に相互変換するヘルパーを使用
- 「保存して閉じる」で`themes.custom`として確定・永続化。「編集前に戻す」（旧称：現在のテーマの色に戻す）は保存せず、開いた時点の値に戻すだけ
- 「今の配色を取り込む」ボタンで、編集画面を開く直前に使っていたテーマ（プリセット・スポイト等）の基本色を下書きに読み込める。編集途中の色がある場合は上書き確認のダイアログを出す

### フールプルーフ

- ✕・Escキー・背景クリックで閉じた場合は、リアルタイム反映していた色を元のテーマに戻す（保存しない）
- 編集モーダルを開くときは設定モーダル自体を閉じ、2つのオーバーレイが重ならないようにする
- スポイトで作ったテーマはスウォッチ一覧に並べず、💧ボタン専用で扱う（`buildThemeSwatches()`のループから`eyedropper`キーを除外）

## 色の設計：基本色と派生色の分離

色を「人が決める基本色」と「そこから自動計算する派生色」の2種類に分ける。

- **基本色**：プリセット定義・カスタム編集画面・スポイト生成のいずれかで決まる16色（15色＋STAGE背景）
- **派生色**：薄い強調色（`-rgb`系）、暗幕、影、選択範囲の文字色（`--on-accent`）、パネル面（`--panel`）、枠線（`--panel-line`）、ヘッダー文字の縁取り（`--text-halo-rgb`）など。テーマ適用のたびに基本色から自動計算し直す（`completeThemeTokens`関数）

これにより、基本色しか持たないカスタム／スポイトテーマでも全項目が揃い、古い保存データ（新項目を持たない）でも前のテーマの色が残らないことを両立している。

新しい派生色を追加する場合は`completeThemeTokens`関数（`js/main.js`）に計算式を追加し、`apps/sideops-theme-bridge.js`側の許可リストにも変数名を追加する必要がある（追加しないとアプリへ届かない）。

## STAGE背景の独立化

STAGE（アプリ）の背景色は、本体の背景色とは独立したテーマ項目（`--stage-bg`）。カスタムテーマ編集画面にも「STAGE（アプリ）背景」の入力欄がある。未設定なら本体の背景色と同じ（従来通りの見た目）。テーマブリッジの詳細は`テーマブリッジ_仕様書.md`を参照。

## ヘッダー・STAGEヘッダーの視認性

- STAGEヘッダーの背景はSTAGE背景の透けではなくパネル色（`--panel`）固定。STAGE背景を暗い色にした際にヘッダーだけ黒くなる見え方を回避
- 本体ヘッダーの下線（`border-bottom`）は無し
- ロゴ・日付・時計は文字色と反対の明るさで縁取り（`text-shadow`を8方向に重ねた輪郭）を付け、壁紙や配色に関わらず読めるようにしている（縁取りの色は`--text-halo-rgb`）

## 設定の永続化

IndexedDB（`sideops_settings`）に、壁紙・透過率・テーマ選択を永続化。

- レコードを2つに分離：`key: 'main'`は軽いデータ（透過率・壁紙の選択値・テーマキー・カスタムテーマとスポイトテーマの色）、`key: 'wallpaperUploads'`は重いデータ（アップロード壁紙のデータURL）
- **フールプルーフ**：アップロード壁紙は1枚5MBまで、永続化は3枚まで（超えたら古いものから自動削除。アップロード自体は拒否しない）
- スポイトテーマは生成時点の色を保存し、リロード後もそのまま再適用する（壁紙を変えても自動では作り直さない）
