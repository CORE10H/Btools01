# アプリ：LIBRARIUM（`apps/librarium.html`）AIのべりすとの本棚 仕様書

## 概要

AIのべりすとで書き出した作品（`.novel`）から**本文だけ**を取り込み、本棚に並べて読む先天的アプリ（`builtin`）。2026-10-07に新設。

- 名前：LIBRARIUM（ラテン語で「書庫」）。ユーザーが候補（NOVELSHELF・LIBRARIUM・STACKS・ARCHIVE）から選んだ
- ランチャー表示名：`LIBRARIUM`（`BUILTIN_APP_CHOICES`）。カバー画像は`apps/img/librarium.jpg`（900×506。`D:\dev\sideops_sync_verify\cover_librarium.dart`が`icon_src/librarium.html`のキャンバスで描いて書き出したもの）
- 1ファイル（HTML＋CSS＋JS）。外部ライブラリなし（ZIPの展開もブラウザの`DecompressionStream`を使う）
- `<head>`で`sideops-theme-bridge.js`（テーマ・同期の印・戻るボタン）と`sideops-frame.js`（表紙の見え方）を読み込む
- 見た目（本棚の表紙・縦書きの題名・読む画面）はMANUSCRIPTの本棚・閲覧画面にそろえた

### MANUSCRIPTとの違い

MANUSCRIPTは「書く」アプリ（ネタ・プロット・章・本文を自分で作る）。LIBRARIUMは「AIのべりすとで書いたものを読む・並べる」アプリで、本文は取り込んだまま（ここでは本文を編集しない）。データも別（DBを分けている）。

## データ（IndexedDB：`sideops_librarium`・版1）

| ストア | キー | 中身 |
|---|---|---|
| `books` | `id`（`lb_…`） | 1冊。`title`・`author`（名義）・`series`・`tags[]`・`memo`・`body`（本文。改行は`\n`）・`chars`（空白と改行を除いた文字数）・`coverImage`（Blob。なければnull）・`coverThumb`（表紙の見え方。任意）・`source`（取り込み元：`kind`＝`novel`/`txt`、`fileName`、`title`＝元の題名、`workId`＝AIのべりすとの作品ID、`savedAt`＝保存した時刻、`hash`＝本文のSHA-256）・`createdAt`・`updatedAt`・`importedAt` |
| `progress` | `id` | 2026-10-07の版の名残。今は使わない（下の`sideops_librarium_pos`へ移し替え、空にする）。同期しない（`excludeStores`） |

**読んだ位置（`sideops_librarium_pos`・版1。2026-10-08〜）**：ストア`progress`（キー＝本の`id`）に`ratio`（0〜1）・`vertical`・`updatedAt`。

- 本と別の**DB**にしたのは、同期がDBごとに1つのファイルを丸ごと送るため。2026-10-07の版では同じDBの別のストアにしていたが、それでは位置が変わるたびに全部の本文まで送り直していた（計測で判明。2026-10-08に直した）
- 開いたとき、古い置き場所（本のDBの`progress`）に記録があれば、1回だけ新しいDBへ移して古い方を空にする（両方にあれば新しい方を残す）
- 位置のDBを開けなくても、本棚と読む画面は使える（位置を覚えないだけ）。本を消すときは、本を消してから位置を消す（別のDBなので1つのトランザクションにはできない。位置だけ残っても害はない）
- 同期の対象（`js/sync.js`の`DB_RULES`に`sideops_librarium`と`sideops_librarium_pos`を追加）。読んだ位置もほかの端末に届く
- 端末ごとの設定（並べ方・文字の大きさ・縦書き）は`localStorage`の`sideops_librarium_prefs`（同期しない）

## .novel の読み方

AIのべりすとの`.novel`はUTF-8（BOMなし）のテキストで、`<|endofsection|>`で区切った欄が並ぶ（参考：AIのべりすと非公式Wiki「novelファイルフォーマット」。2023-06時点の情報）。

| 欄（0から） | 中身 | LIBRARIUMでの扱い |
|---|---|---|
| 0 | 本文。改行は`<br>`、AIが書いた部分は`<span id="ai_output" …>`で囲まれる | 取り込む。`<br>`・`</p>`・`</div>`を改行にし、ほかのタグは外して文字だけにする（`DOMParser`。スクリプトは動かない）。`&lt;`などは文字に戻す。行頭の字下げは残し、行末の空白と前後の空行は削る |
| 1〜5 | メモリ・脚注・パラメータ・キャラクターブック・禁止ワード | 取り込まない |
| 6 | タイトル | 題名にする。空ならファイル名 |
| 7 | 作品ID（数字） | `source.workId`。同じ作品の見分けに使う |
| 8以降 | スクリプト・チャットテンプレート・UUID・保存した時刻（UNIX時間） | 後ろから探した10桁（秒）か13桁（ミリ秒）の数字を保存した時刻にする |

形式が変わっても困らないように、ゆるく読む：区切りが1つもなければ「.novelの形ではありません」とする。題名・作品ID・時刻は、見つからなければ空のまま。

### 会話形式（チャット）の作品（2026-10-08〜）

AIのべりすとのチャットで書いた作品は、本文の中に発言ごとのアイコンが入る：`<img src="images/chat_icon_user00.png" class="chat_icon" alt="[＃ユーザー]">`・`<img src="images/chat_icon_assistant00.png" class="chat_icon" alt="[＃アシスタント]">`（ユーザーから受け取った実物で確認）。この形の作品は発言ごとに分け、取り込みの確認で本文にする発言を選べるようにする。

- 発言の種類：最初のアイコンより前の文（「最初の文」）・ユーザー・アシスタント。アイコンの`src`（user / assistant）か`alt`（ユーザー / アシスタント）で見分ける
- 既定で本文にするのは**アシスタントの発言だけ**。ユーザーの発言・最初の文・断りの返事らしいもの（「お断りします」「申し訳ありません」「そのような内容は〜」等で始まるもの）は外す。断りの返事には「断りの返事らしい」の印を出す
- 確認の画面の「会話形式：本文にする発言 k / N」を開くと、発言ごとのチェックで選び直せる。選んだ発言を空行でつないで本文にする（文字数・見本・本文が同じかの見分けも、選び直した後の本文で）
- 本文にする発言が1つもない本は取り込まない（確認の画面にその旨を出す）
- 取り込んだ本の`source.chat`＝true

### AIの「思考」（`<think>〜</think>`）（2026-10-08〜）

タグのまま（`<think>`）でも、文字として（`&lt;think&gt;`）でも入りうる。

| 形 | 扱い |
|---|---|
| `<think>〜</think>` の組 | 丸ごと除く |
| `</think>` だけ（始まりの印がない） | 会話形式なら、その発言の頭から印までを思考とみなして除く。会話の区切りがない本文では、印だけを消す（どこからが思考か分からないため） |
| `<think>` だけ（終わりの印がない） | 印からその区切りの終わりまでを除く |

除いた数は、取り込みの確認に「思考（<think>）をnか所除きました」と出す。ユーザーの実物（チャットの作品）では、思考は印のない普通の発言として保存されていた（アシスタントの1回目の返事）。そのため、上の会話形式の選び方（断りの返事を外す）で除いている。

## 取り込み

「＋ 取り込む」で選ぶ（複数可）か、本棚にファイルを落とす（PC）。

- **.novel**：上の読み方で1冊
- **ZIP**：AIのべりすとの「ZIPですべてエクスポート」。中の`.novel`だけを読む（ほかは無視）。ZIPの目次（セントラルディレクトリ）を自前で読み、圧縮されたものは`DecompressionStream('deflate-raw')`で展開する。ファイル名がUTF-8でなければShift_JISとして読む（AIのべりすとのZIPはファイル名が文字化けすることがあるため。題名は中身から取るので、表示にしか使わない）
- **.txt**：UTF-8として読めなければShift_JISで読み、そのまま1冊（題名＝ファイル名）。中身が`.novel`の形なら`.novel`として読む

読んだら「取り込みの確認」を出す。1冊ごとに題名を直せて、取り込み方を選べる：

| 見分け | 既定 |
|---|---|
| 本文がまったく同じ本がある（SHA-256が同じ）／同じ取り込みの中に同じ本文がある | 取り込まない |
| 作品IDが同じ本がある | 本文を更新（表紙・名義・シリーズ・タグ・メモはそのまま。題名は、取り込んだときのままなら新しい題名に、自分で変えていたらそのまま） |
| どちらでもない | 新しく追加 |

読めなかったファイルは理由つきで一覧に出す。「取り込む」で、選んだ分を1トランザクションで書く（途中で失敗したら何も保存しない）。

### 歯止め

| 項目 | 上限・扱い |
|---|---|
| 1ファイル（.novel / .txt / ZIPの中の1件） | 30MB |
| ZIP | 300MB・2000件まで。暗号化・ZIP64・未対応の圧縮方式は、その旨を出して飛ばす |
| 展開後の大きさ | 1件30MBを超えたら展開を止める（ZIP爆弾対策） |
| 本文 | 500万文字まで。空の本文は取り込まない（会話形式は、選んだ発言の本文が空なら取り込まない） |
| 表紙の画像 | 5MBまで |
| 表示 | 題名・本文などは`textContent`か`escapeHtml`を通す |

## 本棚

- 表紙（3:4）・題名・名義・文字数・読んだ割合（表紙の下の線と「42%」「読了」）
- 表紙がなければ、縦書きの題名を表紙にする（MANUSCRIPTと同じ作り）
- 表紙は「見え方」（`apps/sideops-frame.js`）の通りに出す
- 並べ方：取り込んだ順・最近読んだ順・題名順・文字数順（端末ごとに覚える）
- 検索：題名・名義・シリーズ・タグ。2文字以上なら本文も探す
- ヘッダーは幅640px以下で2段（1段目＝タイトル・取り込む・☰、2段目＝検索と並べ方）

## 読む画面

- 本をタップで開く。上に「← 本棚」・題名・A−／A＋（文字の大きさ12〜28px）・縦書き／横書き・コピー（本文をクリップボードへ）・情報
- 縦書きは`writing-mode: vertical-rl`。右端が冒頭で、横にスクロールする（マウスのホイールの縦の動きを横に読み替える）
- 読んだ位置：スクロールが止まって1.5秒後・本棚に戻るとき・画面を離れるとき・Stageを閉じる合図（`sideops:stage-closing`）で保存。ほとんど動いていなければ書かない。開き直すと続きから（「前回の続きから（42%）」）
- 縦書き・横書きの切り替え、文字の大きさの変更でも、同じ辺りを表示し続ける（切り替える前に割合を測る）

## 本の情報

読む画面の「情報」から。題名・名義・シリーズ・タグ（「、」か「,」区切り、30個まで）・メモ・表紙（選ぶ・見え方・外す）・取り込み元（ファイル名・形式・元の題名・作品ID・保存した日時・取り込んだ日時・文字数）。

- 表紙を選ぶと、続けて見え方の調整を開く（キャンセルなら中央で切り抜き）
- 変更して保存せずに閉じようとすると「変更を保存せずに閉じますか？」
- 「本文を書き出す（.txt）」：本文をUTF-8のテキストでダウンロード
- 「削除」：確認のうえ、本と読んだ位置を1トランザクションで消す（AIのべりすとの作品やファイルは消えない）

## スマホの戻るボタン（SIDE-OPSのStageの中）

`window.SideOpsBackLayers`に読む画面（`#readerView.is-active`）を足して、読む画面も1段として数える。`window.SideOpsBack`は、モーダルが開いていなければ読む画面を閉じて本棚に戻す（モーダルはいつもの閉じ方に任せる）。戻るボタンで「モーダル → 読む画面 → Stage」の順に閉じる（`core/claude_メインステージ_仕様書.md`「戻る操作」）。
