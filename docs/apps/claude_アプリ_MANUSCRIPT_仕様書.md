# アプリ：MANUSCRIPT（`apps/manuscript.html`）AI執筆特化の小説制作アプリ 仕様書

## 概要

旧来の小説執筆アプリ「manuscript」の簡易版として、AIでの作成に特化させた先天的アプリ（`builtin`）。ネタ帳を書き溜め、ネタから設定プロット、プロットと設定集から章ごとの本文を作り、推敲・公開した完成品を「本」として本棚に保管する。小説だけでなくPV・ショート動画などのビジュアル展開に使う画像（表紙・カバー・章の画像・設定画像）も作品と一緒に保持する。

**生成そのものはアプリの外（外部AI）で行う。** アプリが担うのは「テンプレートに素材を差し込んでプロンプトを作る → 外部AIの出力を貼り戻す → 保存する」だけで、API・APIキーは持たない（SCRIBITと同じ方式。API連携は利用者側の負担も増えるため保留）。

- ランチャー表示名：`MANUSCRIPT`（`BUILTIN_APP_CHOICES`、カバー画像は`apps/img/manuscript.jpg`）
- テーマ追従：`<head>`で`sideops-theme-bridge.js`を読み込み、色はすべてCSS変数で記述
- 本文・閲覧画面のみ明朝体（Shippori Mincho）、それ以外は他アプリ共通のIBM Plex Sans JP

## 画面構成

| タブ／画面 | 内容 |
|---|---|
| ネタ帳 | ジャンルごとのカード（16:9の表紙付き）→ そのジャンルのネタ一覧、の2段構成。ジャンルを1つも作っていない間は全ネタを直接並べる。検索は全ジャンル横断。「§ ネタを取り込む」で一括登録 |
| 制作中 | 本棚未登録の作品一覧。段階（構想／プロット／執筆／推敲）と名義で絞り込み、検索（タイトル・名義・シリーズ・ID） |
| 本棚 | 本棚登録済みの作品を表紙（3:4）で並べる。表紙がなければカバー、どちらもなければ縦書きのタイトルを表紙にする。名義で絞り込み |
| テンプレート | 用途別（7種）のテンプレート管理 |
| 作品エディタ | 下記 |
| 閲覧 | 本を読む画面。目次（2章以上）、章の画像、横書き／縦書き切り替え、本文コピー、章ごとの公開ページへのリンク |

開いたときの画面は**制作中**（2026-10-06〜。それまではネタ帳。HTMLのタブ・画面の`is-active`と、`currentView`の初期値を`works`にしてある）。保存機能を使えないとき（DBを開けない）の案内は、制作中とネタ帳の両方に出す。

### 作品エディタの構成

**作品の土台**（作品に1つ）
1. 元になるネタ（複数可）
2. 設定プロット（作品全体の設計図）
3. 設定集（人物・場所・施設・アイテム・用語・その他。1項目ごとに画像1枚と画像用プロンプト）
4. 作品ビジュアル：表紙（縦3:4、本棚用）とカバー（横16:9、PV・動画用）

**章**（章タブで切り替え。追加・並べ替え・削除。最後の1章は削除不可）

5. 本文（章の筋は任意）
6. この章の要約（次の章の`{{前章まで}}`に使う引き継ぎ資料）
7. 推敲・完成稿
8. 章の画像（横16:9）
9. この章の公開（URL・公開日。note記事IDを自動記録。章単位の.md書き出し）

**本棚・書き出し**：本棚登録、全章の完成稿を.mdで書き出し、作品のJSONエクスポート、作品の削除

名義（ペンネーム）とシリーズは作品ごとに持ち、入力欄は既存の値を候補表示する（表記ゆれ防止）。

作品の段階はデータから自動判定する：完成稿のある章あり→推敲、本文のある章あり→執筆、プロットあり→プロット、それ以外→構想。本棚登録だけは明示フラグ（`isBook`）。

## データ構造（IndexedDB・DB名`sideops_manuscript`・DB version 3、すべて`keyPath: 'id'`）

```
genres    { id, name, note, order, createdAt, updatedAt }
neta      { id, title, body, tags[], genreId('' = 未分類), createdAt, updatedAt }
works     { id, title, penName, series, netaIds[], plot, tpl{用途:テンプレートID}, isBook, bookAt, undo{plot}, createdAt, updatedAt }
chapters  { id, workId, order, title, outline, body, summary, final, publishUrl, noteId, publishedAt, undo{body,summary,final}, createdAt, updatedAt }
lore      { id, workId, kind(person|place|item|term|other), name, body, createdAt, updatedAt }
images    { id(<所有者ID>:<枠>), ownerId, workId, genreId, slot(kv|cover|img), blob, type, name, w, h, updatedAt }
templates { id, kind, name, body, createdAt, updatedAt }
meta      { id, value }   // lastFullExportAt（最後に全件エクスポートした日時）
```

- 画像はBlobのまま保存。枠は「作品の表紙`<作品ID>:kv`」「作品のカバー`<作品ID>:cover`」「章の画像`<章ID>:img`」「設定画像`<設定ID>:img`」「ジャンルの表紙`<ジャンルID>:cover`」。作品に属する画像は`workId`、ジャンルの表紙は`genreId`を持ち、削除・エクスポート時に一括で扱えるようにしている
- ネタは1つのジャンルにだけ属する（フォルダ方式）。存在しないジャンルを指すネタは読み込み時に未分類として扱う
- 作成したプロンプト自体は保存しない（テンプレートと素材から毎回作り直せるため）
- v1（章のない形式。作品に本文・完成稿を直接持つ）のデータは、読み込み時・インポート時に第1章へ自動移行する

## ID方式（重要）

形式：`<接頭辞>_YYYYMMDD_HHMMSS_<英数小文字4桁>`（例：`ms_20260929_153045_a7k2`）

| 接頭辞 | 対象 |
|---|---|
| `nt_` | ネタ |
| `ms_` | 作品 |
| `ch_` | 章 |
| `lr_` | 設定集の項目 |
| `tp_` | テンプレート |
| `gn_` | ジャンル |

- **作成時に1回だけ発行し、エクスポート・インポートを含むどの経路でも変更しない**（例外はインポートで「複製」を選んだときの新規発行のみ）。UIからも編集不可（作品IDはクリックでコピーのみ）
- 末尾4桁は`crypto.getRandomValues`による乱数。既存IDと衝突した場合は再発行する
- 参照（作品→ネタ・テンプレート、章・設定→作品、画像→所有者）はすべてIDで持ち、タイトルでの照合は一切しない

旧manuscriptで「GitHub保存した作品とJSONエクスポートした同一作品が別作品扱いになる」問題の対策として採用。旧manuscriptとの互換は対象外（持ち越し）。

## テンプレートと差し込み

使える差し込み：`{{タイトル}}` `{{名義}}` `{{ネタ}}` `{{設定}}` `{{プロット}}` `{{章番号}}` `{{章タイトル}}` `{{章の筋}}` `{{前章まで}}` `{{本文}}` `{{設定項目}}`。値が空のときは「（なし）」が入る（`{{タイトル}}`は「（未定）」、`{{前章まで}}`は第1章なら「（最初の章です）」）。

| 用途 | 必須 | 使う場所 | 素材が空のときは合成不可 |
|---|---|---|---|
| 設定プロット | `{{ネタ}}` | 土台2 | 紐づけたネタ |
| 作品ビジュアル | `{{プロット}}` | 土台4 | 設定プロット |
| 章の本文 | `{{プロット}}` | 章5 | 設定プロットか章の筋のどちらか |
| 章の要約 | `{{本文}}` | 章6 | その章の本文 |
| 推敲 | `{{本文}}` | 章7 | その章の本文 |
| 章の画像 | `{{本文}}` | 章8 | その章の本文 |
| 設定画像 | `{{設定項目}}` | 設定集の項目 | 名前か説明 |

- `{{設定}}`は設定集の全項目を「## 種類：名前＋説明」で連結したもの。`{{設定項目}}`は開いている1項目だけ
- `{{前章まで}}`は、その章より前の章の要約を「第n章「タイトル」＋要約」で連結したもの。要約が未入力の章があれば、本文プロンプトの合成時に警告する（合成自体は止めない）
- 置き換えは正規表現1回の走査で行う。差し込んだ本文中に`{{本文}}`等の文字列が含まれていても再置換されない
- 初回起動時と、ある用途のテンプレートが0件のとき、その用途の初期テンプレートを作成する（作品ビジュアルは「表紙（縦3:4）」「カバー（横16:9）」の2件）

## ジャンル（ネタのフォルダ）

- ネタ帳タブの「＋ ジャンル」または一覧の「＋ ジャンルを追加」で作成。名前・メモ・表紙（横16:9）を持つ
- ジャンル一覧では表紙とネタ件数を表示。表紙がなければジャンル名を明朝体で表示する。未分類のネタがあるときだけ「未分類」カードが出る
- ジャンルの中で「＋ 新規ネタ」を押すと、そのジャンルに入ったネタができる。ネタの移動はネタ編集画面のジャンル選択で行う
- 作品エディタの「元になるネタ」の選択肢には［ジャンル名］が付く

## ネタの一括取り込み（§区切り）

「§ ネタを取り込む」で開く。**`§` と `§` で挟んだ文章を1件のネタとして取り込む。** 複数同時に可。貼り付けのほか、.txt／.md ファイル（5MBまで、UTF-8）から読み込める（入力欄の後ろに追加）。

```
§1つ目のネタ
改行を含んでもよい§
§2つ目のネタ§
```

- オプション：取り込み先のジャンル（既定は今開いているジャンル）、全件に付けるタグ、「各ネタの1行目をタイトルにする」（オフなら本文のみ。タイトルは一覧で本文の1行目を自動表示）、「同じ内容のネタが既にあれば取り込まない」（既定オン。貼り付けた中での重複も除外）
- 入力中に件数とプレビュー（先頭100件）を表示。取り込み順は貼り付けた順で一覧の上から並ぶ

## 書き出し

| 操作 | 内容 | ファイル名 |
|---|---|---|
| ☰「すべてをエクスポート」 | 全データのJSON（画像はBase64で同梱） | `manuscript_backup_YYYYMMDD_HHMMSS.json` |
| 「この作品をエクスポート（JSON）」 | その作品と章・設定集・画像・紐づくネタ（テンプレートは含めない） | `manuscript_<作品ID>.json` |
| 「全章の完成稿を .md で書き出す」 | タイトル・名義＋完成稿のある章（2章以上なら章見出し付き） | `<タイトル>_YYYYMMDD.md` |
| 「この章の完成稿を .md で書き出す」 | その章の完成稿のみ | `<タイトル>_第n章_YYYYMMDD.md` |

ファイル名の禁則文字（`/ \ : * ? " < > |`）は全角に置き換え、タイトルが空なら「無題」にする（SCRIBITと同じ規則）。

JSON形式：`{ app:"sideops_manuscript", schemaVersion:3, scope:"all"|"work", exportedAt, genres[], neta[], works[], chapters[], lore[], templates[], images[] }`。作品単位の書き出しでは、紐づくネタが属するジャンルとその表紙も含める

## インポート

件数（新規／同じIDあり、作品に含まれる章・設定・画像）を表で確認してから実行。同じIDがあるときの扱いは4択：

- **更新日時が新しい方を残す**（既定。同じ日時なら何もしない）
- **上書き**
- **別の作品として複製**（新IDを発行しタイトルに「（複製）」。中身が完全に同じジャンル・ネタ・テンプレートは増やさず手元のものを共有）

ネタのジャンルは取り込み後のジャンルIDに付け替え、行き先のないジャンルを指すネタは未分類にする。
- **取り込まない**

作品は「章・設定集・画像を含めた1つの束」として扱う。上書き（「新しい方を残す」で置き換わる場合も含む）では、手元にだけある章・設定・画像を削除してから取り込み、作品単位で丸ごと入れ替える。複製では章・設定・画像にも新IDを発行し、参照を付け替える。

## note記事IDの記録（INTEL連携への布石）

章の公開URLが`https://note.com/<ユーザー>/n/<記事ID>`の形なら、記事ID（`n`から始まる文字列）を`chapters[].noteId`に自動で記録する。note記事IDは記事の一意キーとして不変のため、将来INTELパネルの`works`（`note連携_仕様書.md`）と突合する際の鍵になる。note以外のURLは記録のみで記事IDは空。

## フールプルーフ

**保存まわり**
- 自動保存（入力停止から600ms、Promiseチェーンで直列化）。フォーカスが外れた時点・章の切り替え時・画面を離れる時にも即保存
- Stageを閉じる・別アプリに切り替えると、本体から`sideops:stage-closing`の合図が届く（iframeは約1.5秒後に破棄）。合図を受けた時点で保存待ちをすべて書き込む（`メインステージ_仕様書.md`参照）
- 合図が届かない経路（ブラウザのタブを閉じる等）の保険として、`pagehide`・`visibilitychange`でも保存を試みる。保存待ちが残っていれば`beforeunload`で確認
- 保存に失敗した場合は未保存扱いに戻し、次の機会に再試行
- 空のまま閉じた新規ネタ・新規の設定項目、何も入力せずに離れた新規作品は、DBにゴミを残さず削除
- 起動時に`navigator.storage.persist()`を要求。☰メニューで使用量と画像枚数を確認でき、8割を超えたら警告
- **バックアップ忘れの警告**：最後の全件エクスポートから7日以上経つと☰に印が付き、メニューに経過日数を表示（一度もしていない場合はデータ作成日から数える）

**1世代退避（簡易的な取り消し）**
- 対象：設定プロット・本文・要約・完成稿
- 中身の半分以上を選択した状態で貼り付けたとき（＝貼り直し）と、「本文をそのまま完成稿に写す」で完成稿を上書きしたときに、直前の内容を1つだけ退避する
- 欄の上に「直前の上書きを戻す（日時）」が出る。戻すと現在の内容と入れ替えるので、もう一度押せばやり直せる
- 本格的な版管理は手間とのトレードオフで保留（却下ではない）

**ネタの一括取り込み**
- `§` が1つもない／閉じていない`§`がある（奇数個）／中身が空の`§§`／§の外の文章／20万字を超える1件、をそれぞれ件数付きで警告し、該当部分は取り込まない（閉じていない`§`はどこからかを先頭20文字で示す）
- 一度に取り込めるのは500件まで（超えた分は先頭から500件）
- 取り込めるネタが0件なら「取り込む」を押せない
- ファイルは .txt／.md のみ・5MBまで。文字化け（置換文字）を検出したら UTF-8 での保存を促す
- 1件ずつ保存し、失敗しても残りは続行して件数を報告

**ジャンル**
- 削除時は件数を明記し、中のネタは未分類に移す（ネタは消えない）。移動に1件でも失敗したら削除を中止
- 名前が空のまま閉じられない（中身があるとき）。何も入力しなかった新規ジャンルは保存しない
- 同じ名前のジャンルがあれば注意を表示（作成は止めない）

**入力・操作**
- 素材が空のままプロンプト合成はできない（どこを先に埋めるべきかをトーストで案内）
- 本棚登録は作品タイトルと、完成稿のある章が1つ以上必要。完成稿のない章があれば章番号を示して確認（本棚では完成稿のある章だけを表示）。公開URLは`http(s)://`のみ許可し、閲覧画面でも再検証してからリンク化する二重防御
- 公開URLを入力した時点で公開日が空なら、当日を自動入力（変更可）
- 画像はPNG/JPEG/WebP/GIFのみ、5MBまで。実際に画像として読み込めるかを確認してから保存（拡張子だけ偽装したファイルを拒否）。差し替え・削除は確認を挟む。表紙・カバー・章の画像は比率が推奨（3:4／16:9）から10%以上ずれていれば警告（登録は止めない）。枠外へのドロップでブラウザが画像を開いて画面から離れる事故を防止
- **見え方（2026-10-07〜）**：表紙（3:4）・カバー（16:9）・ジャンルの表紙（16:9）・設定画像（一覧の正方形）は、登録すると続けて「見え方の調整」（`apps/sideops-frame.js`）を開き、［決定］で画像の記録に`thumb`（`{ ar, z, cx, cy }`）を保存する（［キャンセル］なら中央で切り抜き）。各スロットの「見え方」ボタンでやり直せる。作品一覧（16:9）・本棚（3:4）・設定集（正方形）・ジャンル一覧（16:9）の枠にその見え方で出す。違う比率の枠に出すとき（表紙がなくカバーを本棚に出す等）も、中心の位置と拡大率を保って出す。章の画像は切り抜かずに出すので対象外。書き出し・取り込み（JSON）でも`thumb`を持ち運ぶ（壊れた値は捨てる）
- 削除確認：ネタは使用中の作品件数を明記（作品側は紐づけのみ外れる）。作品は章数・設定件数・画像枚数を明記して一括削除。章は消える内容を列挙し、最後の1章は削除不可。テンプレートは選択中の作品件数を明記し、各用途の最後の1件は削除不可。テンプレートの用途は編集時に変更不可
- インポート：`.json`のみ・300MBまで。`app`名が違うファイル、アプリより新しい`schemaVersion`は拒否。1件ずつ検証し、不正なもの（所属する作品がない章・設定、2000〜2100年以外の日時等）はスキップして件数を表示。保存失敗も1件単位で握り、全体を止めない
- 表示はすべて`textContent`またはエスケープ済み文字列（XSS対策）。モーダルは`classList`の`is-open`方式のみ

## 既知の注意点・未確認事項

- 縦書き閲覧は検証環境（日本語縦書きフォント無し）では字形が重なって見えた。実ブラウザでの見え方は未確認
- 同じ作品を複数タブで同時に編集すると後から保存した方が勝つ（排他制御なし）
- 旧manuscriptのデータ取り込み（互換）は未対応
- 画像は1枠1枚。差分画像（表情違い等）を複数持つ仕組みはない
