# メインステージ（Stage）仕様書

## 概要

アプリランチャーの表示先。将来的にエージェント（アシスタント）・アバター・画像を表示する予定の予約領域という位置づけも兼ねる。

- 中央バナークリックで、クリック位置起点に拡大するアニメーションで展開。展開時のみ`background:#000`にフェードイン。右上の✕で閉じる
- アプリカードをクリックした場合、`.stage-frame`（`<iframe>`）を`#stageBody`内に動的生成してアプリを表示。閉じるとiframeは破棄する（バックグラウンド実行させない設計）。破棄の手順は下記「iframeの破棄と保存の猶予」
- 「＋新規作成」カードをクリックした場合は、Stageは開かず新規カード作成モーダルが開く

## iframeの破棄と保存の猶予

Stageを閉じたとき・別のアプリに切り替えたとき、古いiframeは`retireStageFrame()`で次の順に片付ける。

1. `display:none`で即座に隠す（見た目上はすぐ閉じる）
2. iframeへ`postMessage({ type: 'sideops:stage-closing' })`を送る（送信先は本体と同じorigin）
3. `STAGE_FRAME_RETIRE_MS`（1500ms）後に`remove()`で破棄する

即座に`remove()`すると、アプリ側の非同期保存（IndexedDBへの書き込み）が途中で打ち切られ、入力直後に✕で閉じた内容が消える（2026-09-30、MANUSCRIPTで実際に再現）。`pagehide`はiframe破棄の瞬間に発火するが、そこから始めた非同期の書き込みは完了しない。

アプリ側の対応は任意（opt-in）。自動保存を持つアプリは、親ウィンドウからの`sideops:stage-closing`を受けたら保存待ちを即時に書き込む。対応していないアプリにも猶予の1.5秒は適用されるため、自動保存の待ち時間（デバウンス）が1.5秒より短いアプリは、合図に対応しなくても猶予中に保存が完了する。現在の対応アプリ：MANUSCRIPT・MINDFRAME

## 戻る操作（スマホの戻るボタン・ブラウザの「戻る」）

スマホの戻るボタン／戻るジェスチャー、PCのブラウザの「戻る」（マウスの戻るボタン・Alt+←）で、いちばん上に開いているものを1つずつ閉じる。順番は開いた順の逆：**本体のモーダル → Stageの中のアプリのモーダル → Stage**。方式は`history.pushState`＋`popstate`（History API）。PC版・スマホ版で共通（レイアウト条件で分岐しない）。

2026-10-05まではStageだけを閉じていた（アプリ内のモーダルは戻る操作の対象外）。2026-10-06に「層」の積み重ねに広げ、仕組みを`js/back-nav.js`（`window.SideOpsBackNav`）に切り出した。

### 仕組み（`js/back-nav.js`）

- **層**：何かを開いたときに履歴を1件積む。積んだ1件ごとに通し番号（seq）と読み込みごとの目印（sid）を付ける
- **戻る操作**：`popstate`で戻った先の番号を読み、それより大きい番号の層を上から順に閉じる（各層を積んだときに渡した「閉じる関数」を呼ぶ）。進む操作で上へ行った場合は、閉じるものがないので何もしない
- **画面の操作で閉じたとき**（✕・キャンセル・背景のクリックなど）：`release(層)`。その層がいちばん上で、今の履歴の位置もその層だと確かめられたときだけ、`history.go(-n)`で自分で消費する（いちばん上から続けて外れる層の数n）。消費しないと、次の戻る操作が「何も起きない空振り」になる
- **戻る操作が届かない場面の代わり**：`backOne()`。いちばん上の層を1つ閉じ、その1件を消費する。全画面表示の解除（下記）で使う

### 何を層として積むか（`js/main.js`）

| 層 | 積むとき | 戻る操作で | 画面の操作で閉じたとき |
|---|---|---|---|
| Stage | `openStage()`の最後（`pushStageHistory()`）。開いたまま別のアプリへ切り替えても積み増さない | `closeStageView()` | ✕：`consumeStageHistory()`がStageとその上のアプリの層をまとめて消費 |
| アプリのモーダル | アプリが「開いているモーダルの数」を知らせてくる（`sideops:back-layers`）。数が増えたら増えた分を積む | アプリに`sideops:back`を送り、アプリがいちばん手前のモーダルを1つ閉じる | 数が減ったら減った分を消費。別のアプリへ切り替えたときは`releaseAppBackLayers()` |
| 本体のモーダル | `SideOpsBackNav.watchOverlay()`で`is-open`の付け外しを見る。対象：設定・カスタムテーマ・アプリ管理・アプリ削除の確認・カード追加・カード削除の確認・同期 | 背景のクリックを送る（だめならEsc） | `is-open`が外れたら消費 |

同期の進み具合（`#syncProgress`）と確認のダイアログ（`#syncDialog`）は答えを待つものなので、層にしない。

アプリ側（`apps/sideops-theme-bridge.js`）の動き：

- 開いているモーダルを`.modal-overlay.is-open, .confirm-overlay.is-open, .editor-overlay.is-open, .view-overlay.is-open, .thumb-lightbox.is-open, dialog[open]`（見えているものだけ）で数え、変わったら本体へ知らせる（`MutationObserver`で`class`・`open`の変化を見て、1回の操作の変化をまとめて1回数える）
- `sideops:back`が来たら、いちばん手前（z-indexが大きいもの、同じなら文書の後ろ側）のモーダルを閉じる。閉じ方は ①背景のクリック ②Esc ③✕ボタン（`.modal-close`等）の順に試す。多くのモーダルは「背景のクリックで閉じる」「Escで閉じる」を持っているので、アプリ側の作業は要らない
- 見つけ方を変えたいアプリは`window.SideOpsBackLayers`（CSSセレクタの文字列）を、閉じ方を変えたいアプリは`window.SideOpsBack`（閉じたら`true`を返す関数）を用意する（2026-10-06時点で使っているアプリはない）
- 2026-10-06に、先天的アプリ10本の全モーダル（54個）が戻る操作で閉じることを確認した（`D:\dev\sideops_sync_verify\backsweep.dart`）。SCAFFOLDだけ背景のクリック・Escで閉じる作りがなかったので足した

### 歯止め

| 歯止め | 内容 |
|---|---|
| 積むのはユーザー操作の中だけ | ユーザー操作なしで積んだ履歴は、Chromeの戻るボタン乗っ取り対策で読み飛ばされ、SIDE-OPSそのものから離れてしまう恐れがある。`navigator.userActivation.isActive`のときだけ積む。例外は、すでに自分の層の上にいるとき（読み飛ばされても行き先は自分の層なので離れない）と、Stage（`force`。同期を待ってから開いた場合も、2026-10-06より前と同じく積む）。アプリの中のタップは、ブラウザの決まりで本体側もユーザー操作の中として扱われる |
| 戻る操作で積み直さない | 同じ理由。閉じたものを開き直さない |
| 1展開につき1件 | 開いたままの切り替え・同じアプリの再クリックでは積み増さない |
| 目印（sid・seq） | 読み込みごとに別の目印を付け、リロード前の古い履歴と取り違えない。自分のものでない履歴は「いちばん下」として扱う |
| 位置を確認してから戻す | 画面の操作で閉じたとき、今いる位置が自分の層だと確認できた場合だけ自分で戻す。途中の層だけを閉じたときは履歴に触らない（戻る操作が1回空振りするだけで、取り違えは起きない） |
| 後片付け中は積まない・開かない | 自分で戻した結果（`popstate`）が届くまでの数十msは、新しく積まない。`openStage()`も受け付けない（`SideOpsBackNav.busy()`）。届かない場合も1秒で解除 |
| 閉じる処理のエラー | 1つの層の閉じる処理がエラーになっても、ほかの層の処理は続ける |
| 再読み込みの途中 | `location.reload()`等の呼び出しの中で`beforeunload`が起きた後は、履歴に触らない・積まない。同期モーダルを閉じたときの再読み込みが、モーダルが閉じたことへの片付け（`history.go(-1)`）で打ち消される不具合が実際に起きたため（2026-10-06、同期の確認で発見） |
| 読み込めなかったとき | `js/back-nav.js`が読み込めなくても本体は動く（戻る操作との連携がなくなり、✕で閉じるだけになる） |

### 全画面表示との関係

Androidのブラウザでは、全画面表示（Fullscreen API）の間の戻る操作は、ブラウザが全画面の解除に使ってしまい、ページには届かない。そのため、⛶ボタン以外で全画面が解けたときは、本体がそれを戻る操作とみなして`backOne()`で1つ閉じ、次のタップで全画面に戻す。詳細は`claude_ヘッダーと設定モーダル_仕様書.md`「全画面表示」。ホーム画面に追加したSIDE-OPS（全画面のアプリとして開く）では、戻る操作は普通に届く。

### アプリ側のルール

- iframe内のアプリは履歴を増やさないこと（`history.pushState`、`location.hash`の書き換え、iframe内でのページ移動）。iframeの履歴はブラウザの中で本体の履歴と1本につながっている（joint session history）ため、アプリが履歴を積むと、戻る操作がまずアプリ内の履歴に使われ、✕で閉じたときの後片付けも正しく働かなくなる。2026-10-05時点の先天的アプリ（builtin）11本は、読み込み・操作で履歴を増やさないことを確認済み
- モーダルは`.modal-overlay`等（上記の見つけ方）に`is-open`を付けて開き、「背景のクリック」か「Esc」で閉じられるようにする。こうしておけば戻る操作で閉じられる

### 既知の制約

- Stageを開いたまま再読み込みした場合（スマホでタブが休止→復帰して読み込み直された場合を含む）、その後の戻る操作が1回、ページの読み込み直しに使われることがある（古い1件が残るため。動作に支障はない）
- インポートしたアプリ（後天的アプリ）や、インターネットショートカット（再実装時）の中でページ移動が起きると、戻る操作はまずそのページ移動を戻す。✕で閉じたときの後片付けも効かず、戻る操作が1回空振りすることがある。インポートしたアプリは`sideops-theme-bridge.js`を読み込んでいないことが多く、その場合アプリ内のモーダルは戻る操作の対象外（Stageごと閉じる）
- アプリが時間をおいてから（操作から5秒ほど経ってから）自分で開いたモーダルは、層を積めないことがある。その場合、戻る操作はStageごと閉じる
- アプリ内の「下の階層」（例：MANUSCRIPTの作品の編集画面からの一覧への戻り）は、モーダルではないので対象外

## 同期との関係（2026-10-06〜）

- `openStage`の頭で`window.SideOpsSyncGate(後で開く関数)`を呼ぶ。開いた直後の同期（`js/sync.js`）の最中は`true`が返る。そのときは開かずに戻り、同期が終わった後に同期側が開き直す（古いデータのまま編集を始めないため）
- 同期は、`#stageEl`の`is-open`と、`#stageBody`内のiframe（閉じた直後の保存の猶予中）で、アプリを開いているかを判定している。開いている間は受け取りをせず、30分ごとに「送るだけ」をする
- Stageを閉じると、保存の猶予の後に、未送信があれば同期が送る

## 3段階の表示モード

排他制御（常にどれか1つ）：

- **通常**：元のGrid枠と同じ左右・上下位置（compact表示）
- **縦いっぱい**（ヘッダーの⇕ボタン）：上端〜下端いっぱいに広げるが、左右幅は通常時のStage枠のまま。カバーフロー・INTEL・LOGパネル等は隠さない
- **四方いっぱい**（ヘッダーの⛶ボタン）：画面全体を覆う完全フルスクリーン。展開中は背後の全パネルを完全に覆い隠す

閉じるボタンの左に2つのアイコンボタンが並び、選択中のものだけハイライトする（同じボタンを再度押すと通常表示に戻るトグル動作）。

## 位置計算

通常・縦いっぱいモードの左右位置は、固定ピクセル値ではなく隣接パネル（`header.top` / `.left-col` / `.right-col` / `.gantt-panel`）の`getBoundingClientRect()`から動的計算する。ウィンドウリサイズにも追従する（`resize`イベントで再計算）。詳細な理由は`3D変形とスタッキングコンテキスト_仕様書.md`を参照。

## カードごとの記憶

選択した表示モードは`cards`ストア（`sideops_launcher`DB）の各レコードに`sizeMode`フィールド（`'normal'` / `'vertical'` / `'full'`）として保存され、IndexedDBに永続化される。カードを閉じて別のカードを開いても混ざらず、リロードしても前回選んだモードが復元される。

## DOM配置上の重要な注意点

`#stageEl`は`.shell`要素の**外側**に配置する必要がある（スタッキングコンテキストの分離によるz-index不具合を避けるため）。詳細は`3D変形とスタッキングコンテキスト_仕様書.md`を参照。

## Stageヘッダーの表示名（`#stageTag`）

表示名を書き換えるのは`openStage()`のみで、`closeStage()`で`--`に戻す（閉じている間は「何も開いていない」ことが分かる）。ランチャーの回転操作では上書きされない（ランチャーはあくまでプレビューで、Stageに実際に何が開いているかとは別物という設計判断）。`.stage-bar`に`min-height: 40px`を指定し、フォールバックフォント差によるヘッダー高さのガタつきを防止している。

## スマホ版レイアウト時の挙動

スマホ版レイアウトの条件（`レスポンシブ対応_仕様書.md`参照）に当てはまる間は、保存されている`sizeMode`に関係なく常に四方いっぱいで開く（`applyStageSizeMode()`内で`effectiveMode = 'full'`に置き換えるのみ。保存値とボタンの選択状態は書き換えない）。表示範囲の切替ボタンは非表示。PC幅に戻れば、そのカードに保存されていたモードに自動で戻る。
