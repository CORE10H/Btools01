# SIDE-OPS 開発ナレッジについて

## 経緯（2026-09-27）

従来、仕様書・設計資料はclaude.aiの「プロジェクトの知識」欄で管理していた。しかし**Claudeはこの知識欄のファイルを直接更新できない**（読み取り専用。書き込み用の公開APIが存在しないため）ことが判明した。

更新のたびに「Claudeが新しいファイルを生成 → ダウンロード → ユーザーが手動でプロジェクトへ再アップロード」という手順が必要で、運用上の手間が大きかった。

そのため、Claudeが直接読み書きできる**GitHubリポジトリ（このリポジトリ）へ運用を移行**し、`docs/`配下に一元化することとした。claude.aiの「プロジェクトの知識」欄は今後使用しない。

## 運用ルール

- 仕様変更・新機能追加のたびに、該当する`docs/`配下のファイルをClaudeが直接読み書きする
- GitHubへの書き込みには都度PAT（個人アクセストークン）が必要。セッションごとに短期発行し、作業完了後に失効させる運用（詳細は`docs/planning/claude_ファイル構成_仕様書.md`参照）

## フォルダ構成・仕分けルール

内容の性質で5種類に分けている。新しいファイルを追加する際は、以下の基準でどのフォルダに置くか判断する。

```
docs/
├── apps/       … 個別アプリ（apps/*.html）1本ごとの仕様書
├── core/       … SIDE-OPS本体（index.html/style.css/js/main.js）の機能ごとの仕様書
├── platform/   … 複数の機能にまたがる技術基盤・実装パターン・環境依存の注意点
├── planning/   … 設計方針・構成・依存関係など、実装そのものではなく「考え方」の記録
└── history/    … 変更履歴（時系列の記録。1ファイルに追記していく）
```

**判断の目安**：「特定の1アプリの中だけで完結する話」→ `apps/`。「本体機能の話」→ `core/`。「複数のアプリ・機能に影響する技術的な仕組みや制約」→ `platform/`。「まだ実装していない設計方針、または実装全体の構成・地図」→ `planning/`。「いつ・何をしたか」→ `history/`。

各フォルダに実際にどのファイルが入っているかは流動的に変わるため、このREADMEには一覧を持たせない。都度`docs/`配下を直接見て確認すること。
