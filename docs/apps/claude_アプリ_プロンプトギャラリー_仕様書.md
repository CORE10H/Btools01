# アプリ：画像生成プロンプト見本一覧（`apps/prompt-gallery.html`）仕様書

## 概要

アプリランチャーから起動する本実装アプリ。ダッシュボード本体とは独立したHTML文書で、デザイントークン（色・フォント）のみ共通の値をこのファイル内に個別定義している（`style.css`には依存しない＝iframeとして単独で動く独立文書のため）。

## データ構造（1件あたり）

画像（Blob）／タイトル／プロンプト本文／ネガティブプロンプト／タグ（複数）／サムネイルの見え方（`thumb`、任意。2026-10-06〜）

`thumb = { ar, z, cx, cy }`（下記「サムネイルの見え方（枠合わせ）」）。この項目を足したとき、同期の`SYNC_APP_BUILD`を`2026100601`に上げた（古い版の端末が`thumb`を知らずに上書きして消さないように。`planning/claude_クラウド同期_仕様書.md`「開発時の決まり」）。

## 保存先

IndexedDB（DB名`sideops_prompt_gallery`）。`entries`ストア（登録データ本体）と`settings`ストア（よく使うタグ・タグの色設定）の2ストア構成。画像はBase64化せずBlobのまま保存（容量膨張を避けるため）。複数の端末の間では、本体の同期（`planning/claude_クラウド同期_仕様書.md`）で受け渡す。

## 一覧表示

グリッド表示。カード＝1件（正方形）。タイトルは画像左上、タグは画像下部にそれぞれ黒グラデーションのオーバーレイ背景を敷いて表示（画像の色に関わらず視認性を確保）。

- 画像は、登録・編集のときに決めた見え方（`thumb`）で表示する。`thumb`がない登録（2026-10-06より前に登録したもの・読めない値）は、以前どおり中央を正方形に切り抜く（`object-fit: cover`）
- **カードをタップ（クリック）すると拡大表示**が開く（2026-10-06〜。PCも2026-10-07〜）。メニューは拡大した画像をタップ（クリック）して出す（下記「サムネイル拡大」）

## ヘッダー

`// PROMPT GALLERY`・検索欄・タグの絞り込みチップ・「＋ 新規登録」・☰ を1段に並べる。幅640px以下（スマホの縦向きなど）では2段にする（2026-10-06〜。以前は検索欄が「＋ 新規登録」に重なっていた）：1段目＝タイトル・「＋ 新規登録」・☰、2段目＝検索欄とタグ。検索欄とタグを`.bar-filter`でまとめ、狭い画面では`.bar-right`を`display: contents`にして、中身を`.app-bar`の並びに直接参加させている。画面の幅が変わったら（回転など）タグを並べ直す。

## カードの上のメニュー（2026-10-07に廃止）

2026-09-26〜10-06は、マウスを乗せる（スマホではタップする）とカードの上に半透明のメニュー（拡大｜編集・プロンプト📋・ネガティブ📋・削除🗑）が出ていた。2026-10-06にスマホでは出さないようにし、2026-10-07にユーザーの希望でPCからも外した。**PC・スマホとも「クリック（タップ）で拡大 → 拡大した画像のクリックでメニュー」**。PCではマウスを乗せるとカードの枠だけ光る（押せることが分かるように）。

## サムネイル拡大（ライトボックス）

画面暗転＋中央表示。`object-fit`で引き伸ばすのではなく`max-width`/`max-height`のみで画面内に収める方式とし、**元画像の実寸（natural size）を超えて拡大しない**。背景クリック・✕ボタン・Escキー・スマホの戻るボタンで閉じる。表示に使うBlob URLはカード描画時に発行済みのものを再利用し、ライトボックス用に新規発行はしない。

### 拡大した画像をタップでメニュー（2026-10-06〜）

操作の流れ：**サムネイルをタップ → 拡大表示 → 拡大した画像をタップ → メニュー**（もう一度タップで隠れる）。以前は「サムネイルをタップ → カードの上にメニュー」だった。

- 拡大した直後は、画面の下に「画像をタップでメニュー」と案内を出す
- メニュー（`.lb-menu`、画面の下に重ねて出す）：題名／「プロンプト📋」「ネガティブ📋」（それぞれ1行。コピーする本文がなければ押せない）／「編集」「🗑 削除」
- 「編集」「削除」は、拡大表示を閉じてから編集画面・削除の確認を開く
- 画像のない登録（以前の登録など）は、最初からメニューを出す

## 登録・編集：サムネイルの見え方（枠合わせ）（2026-10-06〜）

画像を選ぶと、一覧のカードと同じ正方形の枠（`.frame-editor`）に画像が出る。以前は一覧で常に中央を正方形に切り抜いていたため、縦長・横長の画像が見切れていた。

- 操作：ドラッグ（1本指）で位置、ピンチ（2本指）・マウスのホイール・スライダーで拡大縮小。「全体を表示」（画像全体が枠に収まる。余白は背景色）・「枠いっぱい」（短い辺が枠にぴったり＝以前の見え方）・「画像を変更」
- 拡大率`z`：1＝枠いっぱい。最小は全体を表示（縦横比が2:1なら0.5）、最大は4
- 位置`cx`・`cy`：枠の中心に来る画像の上の位置（0〜1）。画像の端が枠の内側に入り込まない範囲に寄せる（動かしすぎても余白が出ない）。枠より小さい向きは真ん中に置く
- `ar`：画像の縦横比（幅÷高さ）。カードを描くたびに画像の大きさを調べずに配置を計算するため、一緒に保存する
- 計算はすべて「枠の一辺＝100」の％で行う（`thumbLayout()`）。カードの大きさが変わっても見え方は同じ
- 新しい画像は「枠いっぱい・中央」から始める。編集では保存済みの見え方を引き継ぐ（縦横比がほぼ同じ＝同じ画像のときだけ）
- 誤作動防止：保存する値は読み込み時に確かめ（`normalizeThumb()`。数でない・範囲外は使わない）、範囲内に寄せる。画像の大きさが読めなかったときは、新しい画像なら見え方なし（中央で切り抜き）、画像そのままの編集なら前の見え方を残す
- 既存の登録を保存するときは、この画面で扱わない項目（新しい版で増えた項目など）も消さずに引き継ぐ（2026-10-06〜。以前は保存のたびに作り直していた）
- 2026-10-07：同じ仕組みを、ほかのアプリのカバー画像でも使えるよう共通部品（`apps/sideops-frame.js`。枠の比率を選べる）にした。PROMPTGALLERYは、登録画面の中に枠を出す作りなので、自分の中の実装のまま

## 入力を捨てて閉じるかの確認（2026-10-07〜）

登録・編集の画面を保存せずに閉じようとしたとき（✕・キャンセル・背景のクリック・Esc・スマホの戻るボタン）、開いた時点から何か変えていたら「入力した内容を捨てて閉じますか？」（`#discardOverlay`：［編集を続ける］［捨てて閉じる］）を出す。何も変えていなければ、そのまま閉じる。

- 変えたかどうか：題名・プロンプト・ネガティブ・タグ（入力途中の文字も含む）・新しく選んだ画像・見え方（枠合わせ。読み込んだ時点の見え方と比べる）
- 確認の上での Esc・背景のクリック・戻るボタンは「編集を続ける」
- スマホの戻るボタン：テーマブリッジが登録画面の背景をクリックしたことにする → 確認が開く → 開いているモーダルの並びが変わったので、ブリッジはそこで止まる（Escまで送ると確認が閉じてしまうため。`core/claude_テーマブリッジ_仕様書.md`）。本体は確認の分の履歴を積み直す（自分の層の上にいるときは、操作の外でも積める決まり）
- 保存したときは確認なしで閉じる

## 検索・絞り込み

タイトル・タグによるテキスト検索、および登録済み全タグから自動生成されるタグチップでの絞り込み。

### タグ絞り込みチップの表示方式（出現頻度順＋幅ベースの動的打ち切り）

- チップは`flex-wrap: nowrap` + `overflow: hidden`とし、2行目に折り返せない構造にする（ヘッダー高さが常に一定になる根本対策）
- 全タグを出現回数の多い順（同数はアルファベット順の安定ソート）に並べ、ヘッダーの実際の幅に収まる分だけ描画する（個数の決め打ちではなく、幅から動的に打ち切る）
- 収まりきらない分は「+n」ボタン1個にまとめ、クリックで全タグを頻度順の縦一覧から選べる「タグで絞り込み」モーダルを開く
- 絞り込み中のタグは常に先頭に固定し、打ち切りの対象から除外する（選択中のタグが「+n」の中に隠れないようにする誤作動防止策）

### サブモーダルのスクロール

「タグで絞り込み」モーダルは、外枠（`.sub-modal`）が`overflow: hidden`で高さの「枠」だけを持ち、実際にスクロールする箇所を`.sub-modal-body`1つに統一している（二重スクロールバー対策）。スクロールバー自体の見た目も、Firefox系（`scrollbar-width`/`scrollbar-color`）とWebKit系（`::-webkit-scrollbar`系）の両方で細く・パネル配色に馴染むものにしている。

## ハンバーガーメニュー（☰）

ヘッダー右端に設置。クリックすると、まず「よく使うタグ」「タグの色」「選択して削除」の3項目だけのシンプルな一覧が開き、各項目を選ぶとそれぞれの専用モーダルが開く二段階構成。

- **よく使うタグ**：ユーザーが任意の文字列を登録・削除できるリスト。登録・編集モーダルのタグ入力欄の下にワンクリック追加／解除できるチップとして表示される
- **タグの色**：現在使われている全タグ＋よく使うタグ登録分に対し、`<input type="color">`（標準カラーピッカー）で任意の色を指定可能。背景色の相対輝度（WCAG簡易計算）から文字色（黒／白）を自動判定し、可読性を確保。反映範囲はカードのタグピル・絞り込みチップ・編集モーダル内のタグピルすべて
  - 配色ルール：未選択（off）時は他のタグと同じ通常の見た目（白字・白枠）、選択中（on）時にのみ設定色を反映する
- **選択して削除**：複数カードをまとめて削除するための選択モード。開始するとヘッダー下に赤い帯で操作ヒントが表示され、検索・タグ絞り込み・「＋新規登録」は誤操作防止のため一時的に無効化される。カードをクリックすると選択トグルし、選択中のカードは画像いっぱいに赤枠＋半透明の赤オーバーレイで「消去」（ゴシック体・赤字）と表示される。ハンバーガーメニューも選択モード中は「モード解除」「削除」の2項目のみに切り替わる。削除は選択件数を明記した確認ダイアログを必ず経由し、実行後は自動的に通常モードへ復帰する

## 既知の注意点

`file://`でローカルファイルを直接開いた場合、Edge/Chromiumの仕様によりIndexedDBが利用できず「保存機能を利用できません」の画面になる。GitHub Pages等のHTTPS環境、またはローカルサーバー（`http://localhost`）経由での確認が必須（詳細は`動作確認の注意点_仕様書.md`参照）。
