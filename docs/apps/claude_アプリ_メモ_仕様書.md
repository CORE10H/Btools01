# アプリ：FIELDNOTES（メモ。`apps/memo.html`）仕様書

## 概要

プロンプトギャラリー（`アプリ_プロンプトギャラリー_仕様書.md`）を土台に実装した、複数メモをカード一覧管理するアプリ。

- 呼び名（2026-11-24〜）：**FIELDNOTES**（現場で書き留める手帳）。ユーザーが「呼称を変更しよう。アイデアください」→ Claude の案（MEMORANDA・FIELDNOTES・MARGINALIA・LOGBOOK・JOTDOWN・FOLIO）から選んだ。変えたのは画面の文字だけ：`<title>`・ヘッダーの `// FIELDNOTES`・ランチャーの「＋新規作成」の選択肢・同期の画面の名前（`FIELDNOTES（メモ）`）。ファイル名・DB名（`sideops_memo`）・`localStorage` のキーは変えていない（保存済みのデータと同期をそのまま使うため）
- すでにあるランチャーのカードの名前は、ユーザーのデータなので書き換えていない（カードの編集で変える）。カバー画像（`apps/img/memo.jpg`）の「メモ」の文字もそのまま
- 一時メモの「ノートへ」から、新しいメモが届く（`一時メモ_仕様書.md`「ノートへ」）。Stage で開いているときは知らせ（`sideops:memo-added`）を受けて、まだ持っていないメモだけを読み足す

## データ構造（1件あたり）

タイトル／本文／タグ（複数）。画像は扱わない（テキスト専用）。

`{ id, title, body, tags, createdAt, updatedAt, folderId?, pinned? }`。`folderId`（入れているフォルダ）と`pinned`（ピン止め）は2026-11-23〜で、無いメモは「未分類」「留めていない」。自動保存はこの2つ（とこれから増える項目）を引き継ぐ（`{ ...既存, 書き換えた項目 }`）。

## 保存先

IndexedDB（DB名`sideops_memo`）。`entries`ストア（メモ本体）と`settings`ストア（よく使うタグ・タグの色設定・フォルダの一覧`folders`）の2ストア構成。プロンプトギャラリーとは別DBのため相互に影響しない。

## 一覧表示

カード＝1件。タイトル（未入力時は本文冒頭を自動使用）・本文抜粋（4行でクリップ）・更新日時・タグピルを表示。「すべて」を見ているときは、日時の前にフォルダ名（📁）。

## フォルダ（2026-11-23〜）

ユーザーの希望：「フォルダ構造みたいなものを導入できそう？」→ 1段のフォルダ（フォルダの中にフォルダは作らない）を提案し、「両方作る」（ピン止めと）で採用。

- 一覧の上に帯（`#folderBar`）：すべて・各フォルダ・未分類・「＋ ／ 編集」（フォルダが無いときは「＋ フォルダを作る」）。数字は中のメモの数。押すとそのフォルダのメモだけを出す。検索・タグの絞り込みと一緒に効く。帯は横にスクロール（スマホでも1行）
- どのフォルダを見ているかは端末ごとに覚える（`localStorage`の`sideops_memo_folder`。`all`・`none`・フォルダのid）。消えたフォルダを覚えていたら「すべて」
- 新規メモは、見ているフォルダに作る（「すべて」「未分類」なら未分類）。メモの中のタイトルの下「📁」の選択欄で入れ替え。選んで（☰ →「選んで削除・移動」）まとめて「フォルダへ移動…」もできる
- フォルダの管理（☰ →「フォルダの管理」、または帯の「＋ ／ 編集」）：追加（「追加」ボタン・Enter）・名前の変更（欄を直して離れる／Enter）・↑↓で並べ替え・削除。一覧は`settings`の`folders`（`[{ id, name }]`、並びがそのまま表示順）
- フォルダとピンの変更では`updatedAt`を変えない（「更新」は中身を書き換えた日時のまま）。書き込みは自動保存と同じ列（`savePromiseChain`）に並べ、書く直前に読み直す（先に並んだ本文の保存を古い本文で上書きしない）
- 歯止め：
  - 名前は空・同じ名前・「すべて」「未分類」を受け付けない。30文字まで。50個まで。変換を確定する Enter では作らない
  - 削除は2回押し（1回目で「もう一度で削除（n件は未分類へ）」、3秒で元に戻る）。**中のメモは消さず「未分類」へ**。見ていたフォルダを消したら「すべて」へ
  - フォルダを先に消してからメモの印を外す。途中で止まっても、またほかの端末で消したフォルダの印が残っていても、無いフォルダの印は「未分類」として見せる（`folderOf`）
  - 選んでいる間（選択モード）は帯を押せない（見えていないメモを選んだまま消さないように）
- 選択モードは「選択して削除」から「選んで削除・移動」に。選んだカードの印は「消去」から「選択」に（削除は今まで通り確認を出す）
- 同期：`SYNC_APP_BUILD` 2026112301。`DB_VERSION`は変えていない

## ピン止め（2026-11-23〜）

ユーザーの質問「ピン止め機能あったっけ？」→ 無かったので作った。

- カードの📌（ホバーで出る。指で使う端末では薄く出しっぱなし）・メモの中の「📌 ピン止め」で留める／外す。保存前の新規メモでも押せる
- 留めたメモは、どの並び順でも一番上（その中は選んだ並び順）。カードの左にアクセント色の線
- 外すと`pinned`の項目ごと消す

## 並び順（2026-10-10〜）

ヘッダーの選択欄（`#sortSelect`）で選ぶ。6通り：更新が新しい順（既定。以前からの並び）・更新が古い順・作成が新しい順・作成が古い順・タイトル順・タイトル逆順。

- タイトル順は、カードに出ているタイトル（未入力なら本文の冒頭）で比べる。`Intl.Collator('ja', { numeric: true })` で、数字は数として比べる（メモ2 → メモ10）
- 同じ値どうしは、更新が新しい順、それでも同じならidの順（並びが理由もなく入れ替わらないように）
- 検索・タグの絞り込みと一緒に効く。並べるのは描画のたび（`renderGrid`）なので、書いたメモは閉じたときに正しい位置へ移る（以前は再読み込みまで元の位置のままだった）
- 選んだ順は端末ごとに覚える（`localStorage`の`sideops_memo_sort`）。同期されるDB（`settings`ストア）には入れない（端末ごとの好みのため）。覚えている値が6通りのどれでもないとき・`localStorage`が使えないときは「更新が新しい順」
- メモのデータの形は変えていない（`SYNC_APP_BUILD`は上げていない）

## キー操作（2026-10-10〜）

| キー | 場所 | 動き |
|---|---|---|
| `Esc` | メモを開いているとき | 保存してから閉じ、一覧へ戻る（✕と同じ） |
| `Esc` | そのほか | 削除の確認・よく使うタグ・タグの色・「+n」の画面・☰メニューを閉じる |
| `Enter` | タグの入力欄 | タグを足す（スマホの決定・改行でも。下の「タグの入力」） |
| `Enter` | 「よく使うタグ」の入力欄 | よく使うタグに足す |
| `Tab` / `Shift+Tab` | メモを開いているとき | 下の順に回る（逆回り） |
| `Enter`・`Space` | ✕にいるとき | 閉じて一覧へ戻る |

Tabの順：タイトル → タグの✕（付いている数だけ）→ タグの入力欄 → よく使うタグ → 本文 → ✕（一覧へ戻る）→ タイトル → …（循環）

- 以前は本文の次が「このメモを削除」で、その先はメモの外（後ろに隠れている一覧の検索欄など）へ抜けていた
- 「このメモを削除」は`tabindex="-1"`でTabでは止まらない（本文の次で押し間違えないように）。クリック・タップでは押せる
- ✕にいるときは枠（`:focus-visible`）で分かるようにした。ツールチップは「一覧へ戻る（Esc）」
- 歯止め：それでもメモの外へフォーカスが行ったら（`focusin`）、タイトルに戻す。削除の確認を出している間は何もしない
- 歯止め：日本語の変換中のキー（`isComposing`、または`keyCode` 229）は扱わない。変換を`Esc`で取り消したときにメモを閉じない、変換を確定する`Enter`で変換前の文字がタグにならない、MS-IMEが変換中の`Tab`で予測候補を選ぶのを邪魔しない
- 確認：`D:\dev\sideops_sync_verify\memo_e2e.dart`（並び順・Tab・変換中のキー。一時メモの確認も同じファイル）

## タグの入力（2026-11-23〜）

ユーザーの報告：「メモ詳細の、タグ入力時、スマホで決定押しても文言がタグ化しない」。

- 原因：スマホ（Android の日本語キーボードなど）は、キーを押したときの`keydown`で Enter を知らせないことがある（`key`が`Unidentified`・`keyCode`が 229 で届く）。以前は`keydown`の Enter だけを見ていたので、スマホでは反応しなかった
- いまは入力欄を**1行の`textarea`**にして、「改行が入った」ことを`input`で見てタグにする。改行の入力はどのキーボードでも`input`で届くので、`keydown`の届き方に左右されない。改行は入力欄に残さない
  - PC：Enter（`keydown`）でタグにする（以前と同じ）
  - 貼り付けた文字に改行があれば、行ごとに別のタグにする（空行・付いているタグは足さない）
  - 入力中だけ「＋追加」ボタンを出す（キーボードに頼らない逃げ道）。押しても入力欄からフォーカスを外さない（スマホでキーボードが閉じない）。`tabindex="-1"`でTabの順は変えない
- 歯止め：日本語の変換中は待つ（変換を確定する Enter・決定ではタグにしない。確定のあと、もう一度の決定・改行でタグになる）。変換中に改行が入った場合は`compositionend`のあとで見る
- 確認：`D:\dev\sideops_sync_verify\memo_tag_e2e.dart`（PC の Enter・スマホの 229＋改行・変換中・＋追加・複数行の貼り付け・保存・本文コピー・一時メモの縁）
- フォルダ・ピン止めの確認：`D:\dev\sideops_sync_verify\memo_folder_e2e.dart`（作る・名前・並べ替え・2回押しの削除・選んで移動・ピンの並び・保存の順番・再読み込み・スマホ幅。49項目）

## 本文のコピー（2026-11-23〜）

ユーザーの希望：「メモ詳細に『（内容を）コピー』のボタンが欲しい」。メモを開いたときの上の帯、✕ の左に「コピー」。**本文**をクリップボードへ写す（タイトル・タグは入れない）。本文が空なら「本文がありません」と知らせてコピーしない。クリップボードの許可がない環境では古い方法（`execCommand('copy')`）でも試す。`tabindex="-1"`でTabの順（本文 → ✕）は変えない。

## ヘッダー

`// MEMO`・検索欄・タグの絞り込みチップ・並び順・「＋ 新規メモ」・☰ を1段に並べる。幅640px以下（スマホの縦向きなど）では2段にする（2026-10-06〜。以前は検索欄が「＋ 新規メモ」に重なっていた）：1段目＝タイトル・並び順・「＋ 新規メモ」・☰、2段目＝検索欄とタグ。作りはPROMPTGALLERYと同じ（`アプリ_プロンプトギャラリー_仕様書.md`「ヘッダー」）。画面の幅が変わったら（回転など）タグを並べ直す。

## 保存方式（自動保存・保存ボタンなし）

入力停止から600ms後にデバウンス保存。以下の誤作動防止策を組み込んでいる：

- 保存処理をPromiseチェーンで直列化し、連続入力による多重実行を防止
- タイトル・本文・タグすべて空のままエディタを閉じた場合、DBにゴミデータを残さず自動削除
- エディタを閉じる操作（✕・Esc・外側クリック）の際は、デバウンス待機中の変更を即座にflushしてから閉じる（変更の取りこぼし防止）
- 保存待ち中にページ離脱しようとした場合、`beforeunload`でブラウザ標準の確認ダイアログを表示

## タグ機能・選択削除モード

プロンプトギャラリーのロジックをそのまま流用（よく使うタグ・タグの色・絞り込み・検索・選択削除モード）。単一メモ内で複数タグを扱える、「複数メモをリスト管理」構造。

タグ絞り込みチップの「+n」方式・二重スクロールバー対策（`アプリ_プロンプトギャラリー_仕様書.md`参照）も同じ内容で実装済み。

## 削除確認

自動保存には「元に戻す」がないため、削除操作のみ確認ダイアログを必ず経由する。

## モーダルの開閉方式（重要な実装ルール）

モーダルを新設・改修する際は、`classList.add('is-open')`方式とHTML側のインライン`display:none`を絶対に混在させないこと。インラインでdisplay:noneを固定すると、CSSクラス側の`display:flex`が詳細度で負けて開かなくなる。新設するオーバーレイは、インラインstyleで開閉に関わるプロパティを指定せず、CSSクラス（基本形の非表示＋`.is-open`での表示）だけで完結させる。

（過去にこのアプリ固有で、「よく使うタグ」「タグの色」モーダルがインラインの`display:none`により一度も開けない不具合が発生し、修正済み。同じ日に新設した「タグで絞り込み」モーダルも`style.display`直接操作方式から`classList`方式に統一した。）
