# 機能間依存関係マップ

各仕様書がどの機能に依存し、どの機能から参照されているかの見取り図。改修時に影響範囲を確認する用途。

## 全体構造

```
                        ┌─────────────────┐
                        │  3D変形とスタッキング │
                        │  コンテキスト（技術基盤）│
                        └────────┬────────┘
                                 │ 影響
              ┌──────────────────┼──────────────────┐
              ▼                  ▼                  ▼
      ┌───────────────┐  ┌──────────────┐  ┌──────────────────┐
      │ アプリランチャー │  │ メインステージ │  │ ヘッダーと設定モーダル │
      │（カバーフロー）  │─▶│  （Stage）    │  │  （3D傾斜50度固定含む）│
      └───────┬───────┘  └──────┬───────┘  └─────────┬────────┘
              │ 起動          │ 表示先              │ テーマ・壁紙・
              │              │                     │ アプリ管理導線
              ▼              ▼                     ▼
      ┌────────────────────────────────────┐  ┌──────────────┐
      │           各アプリ（apps/*.html）      │◀─┤ テーマブリッジ  │
      │ プロンプトギャラリー系／メモ／Discotica／ │  │(postMessage方式)│
      │ DONE MORE／SCRIBIT／SCAFFOLD           │  └──────────────┘
      └──────────────┬─────────────────────┘
                      │ 共通実装パターン
                      ▼
              ┌──────────────────┐
              │ IndexedDB実装パターン │
              └──────────────────┘
```

## 主要な依存関係

### アプリランチャー → メインステージ
中央バナークリックでStageにiframeを生成する。カードの`sizeMode`はランチャー側の`cards`ストアに保存されるが、実際の表示制御はメインステージ側の`applyStageSizeMode()`が担う。両者は同じ`sideops_launcher`DBを介して連携する。

### アプリランチャー ⇄ 各アプリ
ランチャーの`apps`ストアは各アプリ本体への「参照」のみを持つ（実体は持たない）。各アプリが使うIndexedDB（`sideops_memo`等）はアプリ本体のJSコードが指定して初めて紐づくため、ランチャー側の設計変更（カード削除等）は各アプリのデータに影響しない設計になっている。アプリ管理画面（後天的アプリ削除）だけは例外で、アプリ本体を消すとランチャー側のカードが連鎖削除される。

### ヘッダーと設定モーダル → テーマブリッジ → 各アプリ
設定モーダルで変更したテーマ・壁紙・透過率は、まずヘッダーと設定モーダル側で基本色→派生色への変換（`completeThemeTokens`）が行われ、その結果がテーマブリッジ経由で各アプリへpostMessageされる。新しい派生色を追加する場合、ヘッダーと設定モーダル側の計算式追加と、テーマブリッジ側の許可リスト追加の両方が必要（片方だけでは反映されない）。

### 3D変形とスタッキングコンテキスト → アプリランチャー／メインステージ／ヘッダーと設定モーダル
カバーフローの3D傾斜、Stageのフルスクリーン化、設定モーダルの表示は、いずれも同じ「`perspective`によるスタッキングコンテキスト分離」の問題を抱えている。新しいオーバーレイ（モーダル・ダイアログ）を追加する際は、この仕様書のルール（`.shell`の外に置く）を必ず確認すること。

### レスポンシブ対応 → アプリランチャー／メインステージ
スマホ版レイアウトでは、メインステージの表示モードが強制的に「四方いっぱい」になり、アプリランチャーの3D傾斜・PC用固定パーツ（`#cfOpenHit`等）が無効化される。CSSとJSで同じ判定条件（`MOBILE_LAYOUT_QUERY`）を共有しており、両方を同時に変更する必要がある。

### 各アプリ → IndexedDB実装パターン
プロンプトギャラリー・PROMPTGALLERY RED・メモ・Discotica・DONE MORE・SCRIBIT・SCAFFOLD・MANUSCRIPTはいずれも同じDB初期化・CRUD・フォールバックの定型パターンを踏襲している（共通モジュール化はされておらず、コピーによる独立実装）。新しいアプリを追加する際はこのパターンを土台にする。

### メモ → プロンプトギャラリー
メモアプリはプロンプトギャラリーのタグ機能（よく使うタグ・タグの色・絞り込み・選択削除モード）のロジックをそのまま流用している（別実装のコピー。共通化はされていない）。プロンプトギャラリー側の仕様変更は自動的にはメモへ反映されない。

### プロンプトギャラリー → PROMPTGALLERY RED
PROMPTGALLERY REDはプロンプトギャラリーの機能・ロジックをそのままコピーした派生版（別ファイル・別DB）。差分は強調色の配色（アプリ固有の赤、テーマブリッジ非追従）のみ。プロンプトギャラリー側の仕様変更は自動的にはREDへ反映されない（メモと同じ「コピーによる独立実装」の関係）。詳細は`アプリ_プロンプトギャラリーRED_仕様書.md`参照。

### MANUSCRIPT ⇄ SCRIBIT
「テンプレートに素材を差し込んでプロンプトを合成→外部AIに貼る→結果を貼り戻す」という同じ型を持つ。SCRIBITが1本の下書きを1工程で扱うのに対し、MANUSCRIPTはネタ→プロット→本文・キービジュアル→推敲の4工程を1作品IDで束ね、完成品を「本」として保管する。コードは共有しておらず、コピーによる独立実装。

### MANUSCRIPT → note連携（INTELパネル）
MANUSCRIPTは章の公開URLからnote記事ID（`n`から始まる不変の文字列）を`chapters[].noteId`として記録している。INTELパネルの内部データ`works[].platformIds`（`note連携_仕様書.md`）を実装する際は、この記事IDで突合できる。現時点ではデータの受け渡しは未実装（DBも別）。

### SCAFFOLD ⇄ SCRIBIT
どちらも「執筆準備プロンプトの生成→外部LLM生成→整形」という同型の役割を持つが、SCAFFOLDは③（LLM出力を固定見出しで解析しAIのべりすとの複数入力欄へ分別するパース処理）を必須で持つ点がSCRIBITと本質的に異なる。統合案は検討したが、パースの有無で必要な工程数・データ構造が変わり複雑化するため見送り、独立アプリとして維持する方針で確定（`アプリ_SCAFFOLD_仕様書.md`参照）。

### note連携 → INTELパネル（ダッシュボードパネル群）
note連携で設計されているINTELパネルの内部データ構造（readers/works/transactions/followerLog）は、ダッシュボードパネル群のINTEL表示面（売上・稼働時間・コスト・純利益の4枠）への反映方法が未設計のまま。実装時はnote連携の仕様書のチェックリストに従う。

### タスクパネル（ダッシュボードパネル群） → DONE MORE
タスクパネルは表示のみでデータを持たず、DONE MORE側のDB（`sideops_donemore`）と連携する設計だが未実装。

## 改修時の確認ルート（例）

- **新しいアプリを追加する場合**：`アプリランチャー_仕様書.md`（builtin登録）→`IndexedDB実装パターン_仕様書.md`（DB設計）→`テーマブリッジ_仕様書.md`（テーマ追従が必要なら`<head>`で読み込み）→`ファイル構成_仕様書.md`（カバー画像・ファイル配置）
- **モーダル・オーバーレイを新設する場合**：`3D変形とスタッキングコンテキスト_仕様書.md`（`.shell`外配置のルール）→`アプリ_メモ_仕様書.md`のモーダル開閉ルール（`classList`方式の徹底）
- **スマホ対応を触る場合**：`レスポンシブ対応_仕様書.md`を先に読み、CSSとJSの条件を必ず同時変更する
- **色・テーマ関連を触る場合**：`ヘッダーと設定モーダル_仕様書.md`（基本色/派生色の設計）→`テーマブリッジ_仕様書.md`（アプリへの反映）
