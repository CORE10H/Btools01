# テーマ連携（テーマブリッジ）仕様書

## 概要

本体のテーマ（プリセット・カスタム編集・スポイト生成）を、Stage内で開いている各アプリへ反映させる仕組み。色の基本設計（基本色・派生色の分離、STAGE背景の独立化）は`ヘッダーと設定モーダル_仕様書.md`を参照。

## 仕組み（postMessage方式）

本体側（`js/main.js`）が`:root`のstyle変化をMutationObserverで監視し、変化のたびにStageのiframeへ`postMessage`でテーマ色一式を送信する（プリセット切替・カスタム編集中のライブ反映・スポイト生成、どの経路で色が変わっても同じ1本の監視で拾える）。

受信側は共通スクリプト`apps/sideops-theme-bridge.js`で、各アプリが`<head>`で1行読み込むだけのopt-in方式（読み込んでいないアプリには何も起きない＝既存アプリを壊さない）。

## フールプルーフ

- 受け取るのは許可リストの変数名かつ値の形式が妥当なものだけ（不正な値でCSSを壊されない・注入されないための対策）
- 直近に受け取った色は`sessionStorage`に控え、次に開いた瞬間に先回り適用してダークからのチラつきを防ぐ
- 単体で直接開いた場合（親ウィンドウが無い）は何もしない

## STAGE背景の受け渡し

アプリ側では`sideops-theme-bridge.js`がSTAGE用の色をアプリ内の「下地の色」として読み替えるため、各アプリのCSSは`--bg`等の記述を変えずに追従する。

## 固定色の変数化

本体・全アプリ・Discoticaのスクリプトに残っていたダーク前提の固定色（暗幕、画像上の黒グラデ、影、薄い強調色の下地など約50箇所）を、派生色変数に置き換え済み。プロジェクト色・ユーザーが付けたタグ色などアプリ固有の色（ユーザー自身が選ぶ色）は対象外。既定のダークテーマは、この置き換えの前後で画素単位で差分が無いことを確認済み。

## CSS変数だけでは追従できないアプリ

反映後に`document`へ発火する`sideops:themechange`を拾えば、canvas描画や色を解決済みで描くSVGも追従できる。MINDFRAMEは、画面とPNG書き出しの見た目を一致させるためにテーマ色を実際の色コードに解決して描いており、このイベントで色を読み直して全体を描き直している（`アプリ_MINDFRAME_仕様書.md`参照）。

## 同期のための「変えたよ」の印（2026-10-06〜）

テーマとは別の役目として、同期（`js/sync.js`）のための印を付ける処理も、このファイルの先頭に入れた。全アプリが読み込むので、各アプリを直さずに済む。

- アプリがIndexedDBに書き込む（`put` / `add` / `delete` / `clear`、カーソルの`update` / `delete`）と、`localStorage`に`sideops_sync_dirty:<DB名>|<ストア名>`＝時刻を残す
- 同期は、この印があるDBだけを見直す（毎回すべてのデータを読み直さずに済む）
- 単体で開いた場合も印を付ける（テーマの受信とは違い、親ウィンドウがなくても動く）
- 大量に書き込むとき（取込など）は、0.5秒に1回にまとめる。最後の書き込みの後にも1回残す
- 印を付けられなくても、アプリの動作には影響させない（すべてtryで囲む）
- **新しいアプリも、このファイルを読み込むこと**。読み込まないと、そのアプリの変更は☁を押したとき（または1日1回の見直し）まで同期されない
- できるだけ`<head>`の早い位置で読み込む。アプリの最初の書き込みより後に読み込まれると、その書き込みには印が付かない

## 新しい派生色を追加する場合の手順

1. `js/main.js`の`completeThemeTokens`関数に計算式を追加
2. `apps/sideops-theme-bridge.js`側の許可リストに変数名を追加（追加しないとアプリへ届かない）
