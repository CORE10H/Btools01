# レスポンシブ対応（スマホ対応）仕様書

## 基本方針

- **スマホは「アプリを起動して使う」ための別レイアウトと割り切る。** INTEL・LOG・TIMELINE・タスクの4パネルは丸ごと非表示にし、残すのはヘッダー・カバーフロー（ランチャー）・Stageだけ
- **切り替えはメディアクエリの条件だけで行う。** 縦方向のリサイズ監視や、パネルの自動折りたたみは一切入れない
- **PC用の既存ルールは1行も書き換えない。** `style.css`末尾のスマホ版ブロック（`@media`）で上書きするだけで完結させる。この`@media`ブロックを消せば、完全にPC版だけの状態に戻る
- JS側も同じ条件文字列を`matchMedia`で判定し、CSSとJSの判定を必ず一致させる
- タブレット幅など中間サイズの段階的な崩し方は、意図的に対応しない

## 適用条件

次のどちらかに当てはまれば、スマホ版レイアウトになる。

| 条件 | 対象 | 理由 |
|---|---|---|
| `max-width: 479px` | 縦向きのスマホ（Xperia 5 IIで論理幅412px） | 幅が狭く、3カラムが成立しない |
| `max-height: 500px` | 横向きのスマホ（Xperia 5 IIで約915×412px） | 横にすると幅が900pxを超えて幅の条件から外れるが、高さが足りず全パネルが上下に潰れる。問題の本質は「高さが足りない」ことなので、高さで拾う |

**同じ条件を2か所に書いている（必ず同時に変えること）**：

- `style.css`：`@media (max-width: 479px), (max-height: 500px) { … }`
- `js/main.js`：`const MOBILE_LAYOUT_QUERY = '(max-width: 479px), (max-height: 500px)';`

片方だけ変えると、見た目はスマホ版なのにJSはPC版として動く（またはその逆）という食い違いが起きる。

**既知の挙動（仕様）**：PCでもブラウザウィンドウの高さを500px以下に縮めると、スマホ版レイアウトに切り替わる。開発者ツールを画面下に大きく開いた場合も同様。高さ500px以下ではPC版の4パネルはどのみち潰れて使えないため、この挙動は許容している。

## CSS（`style.css`末尾のスマホ版ブロック）

- `.shell`を1カラム・2行のグリッド（`header` / `left`）に変更。高さは`100dvh`（アドレスバーの出入りでズレないように）、非対応ブラウザ向けに`100vh`を先に書いてフォールバックにしている
- `.right-col`（INTEL・LOG）・`.timeline-panel`・`.task-panel-left`を`display: none`
- `.left-col`の3D傾斜を`transform: none`で解除（見えている場所＝触れる場所にする）
- `.cf-wrap`に`touch-action: none`（ブラウザ標準のスクロールや引っ張って更新を止め、縦スワイプをJSだけに渡す）と`overflow: hidden`（上下端のはみ出しを切る）
- `.cf-wrap`に`max-width: min(100%, 74vh)`と中央寄せ。横向きで幅いっぱいに広がると16:9のカードが高くなりすぎて画面からはみ出すため、幅に上限を設ける
- PC用の固定座標パーツを無効化：`#cfOpenHit`（透明な当たり判定の層）・`.cf-nav-fixed`（▲▼ボタン）・`.cf-head-fixed`（APPSラベル）を`display: none; pointer-events: none`。スマホでは「スワイプ」と「脇のカードをタップして中央へ」で操作する
- ヘッダー：`.header-date`（日付）を非表示にし、ロゴ・時計・アイコンだけ残す。アイコンボタンは指で押しやすい36px角。2026-10-10、ボタンが4つ（✎ 一時メモ）になったため、420px未満では幅に応じて間隔と文字を詰める（`core/claude_ヘッダーと設定モーダル_仕様書.md`「スマホのヘッダーの詰め方」）。このブロックの直後に、幅だけを条件にした別の`@media`として書いている
- Stage：表示範囲の切替ボタンを非表示（JS側で常に四方いっぱいにするため）。閉じるボタンは36px角。一時メモの ✎ も36px角で、閉じるボタンの左
- 一時メモ：ボタン・つまみ・右下の角を指で扱える大きさに（`core/claude_一時メモ_仕様書.md`）

**横にあふれていないかの確かめ方**：ヘッドレスEdgeの`Emulation.setDeviceMetricsOverride`で`mobile: true`にすると、中身が画面より広いときは本物のスマホと同じく画面全体が縮んで広がる（`innerWidth`が指定の幅より大きくなる）。`document.documentElement.scrollWidth <= innerWidth`だけでは見逃すので、`innerWidth`が指定の幅のままかも確かめる（2026-10-10、ヘッダーのボタンを足したときにこれで見つけた）。

## JS（`js/main.js`）

- **判定**：`isMobileLayout()`は`window.matchMedia(MOBILE_LAYOUT_QUERY).matches`を返すだけ。`window.innerWidth`との自前比較は使わない（スクロールバー幅などでCSSとズレる瞬間があり得るため）
- **Stage**：`applyStageSizeMode()`内で、スマホ版の間だけ`effectiveMode = 'full'`に置き換える。保存済みの`sizeMode`とボタンの選択状態は書き換えない（`メインステージ_仕様書.md`参照）
- **戻る操作**：スマホの戻るボタン／戻るジェスチャーでStageを閉じる。PC版と共通の仕組みで、スマホ版だけの分岐は持たない（`メインステージ_仕様書.md`「戻る操作」参照）
- **カバーフローの描画（`render()`）**：スマホ版では`translateZ`（奥行き）と`rotateX`（傾き）だけを0に固定。`scale`（脇のカードの縮小）・`opacity`（不透明度のグラデーション）・`transition`（アニメーション）はPC版と同じ計算のまま残す
- **カード間隔（`ySpacing`）**：PC版は60px固定、スマホ版は`Math.round(cardH * 0.62)`（カードの高さに連動）
- **縦スワイプ**：`document`全体で`touchstart`/`touchmove`/`touchend`/`touchcancel`を受け、指が最初に触れた要素が`e.target.closest('.cf-wrap')`に当てはまるかだけで判定する
- **PC⇔スマホの切り替わり**：`mobileLayoutMql`の`change`イベントで`render()`と`positionOpenHit()`を呼び直す。古いSafari向けに`addListener`のフォールバック付き。スマホ版のままトラック幅が変わった場合も、`resize`で`render()`を呼んで間隔を追従させる

### スワイプの誤作動防止策

| 対策 | 内容 |
|---|---|
| スマホ版のときだけ有効 | PCはホイールと▲▼ボタンで操作 |
| 重なっている要素は自動で対象外 | Stageやモーダルが上にあれば、触れた要素がそちらになるので`.cf-wrap`判定に当たらない |
| 閾値40px（`SWIPE_THRESHOLD_PX`） | わずかな指のブレでは送らない |
| 1スワイプ＝1枚 | 一度送ったら指を離すまで送らない（連続送りしない） |
| 横方向が優勢なら無視 | 斜めの誤操作対策 |
| 2本指以上は対象外 | ピンチ操作などと干渉しない |
| 送った直後400msはクリックを捨てる（`SWIPE_CLICK_GUARD_MS`） | 指を離した位置のカードが「タップ」扱いされてアプリが開くのを防ぐ。キャプチャ段階で拾い、カード側のクリック処理に届く前に止める |

## 検証結果

- **縦向き（412×780、タッチ有効）**：実機（Xperia 5 II）で確認済み。上下スワイプで1枚ずつ送れる、脇のカードをタップすると中央へ、中央タップでStageが四方いっぱいで開く、切替ボタン非表示、PC幅に戻すと保存済みモードに戻る
- **横向き（915×412）**：自動検証のみ確認済み。**実機確認は未実施**
- **PC版の非回帰**：1920×1080／1400×800／1024×700の3サイズで、主要要素11種の位置とサイズを変更前後で比較し完全一致

Playwrightでのタッチ操作は、CDPの`Input.dispatchTouchEvent`で再現する。一連のタッチ操作（開始→移動→終了）は1回の呼び出しの中で完結させること（複数回に分けると途中の状態が保たれず正しく検証できない）。

## 経緯：一度目の実装は全面ロールバックした（過去の教訓）

一度目のスマホ対応では、横幅に応じた3段階の崩し方（999px／699px／479px）、`resize`監視による縦方向の判定と、パネルごとの自動折りたたみ、パネルごとの「消え方のルール」を積み重ねていた。条件の組み合わせが増えるたびに別の箇所が壊れ、最終的にウィンドウの異常縮小などの不具合が連鎖したため、丸ごと取り消して現行方式（メディアクエリのみでの一括切り替え）に再構築した。

**反省点**：

- 状態の組み合わせ（横幅3段階×縦方向の折りたたみ×パネルごとのルール）が多すぎて、どれかを直すと別の組み合わせが壊れた
- 一度に複数の変更を積み、一つずつの検証が追いつかなかった
- JSがウィンドウサイズを監視してDOMを書き換える仕組みは、CSSだけで済む仕組みに比べて壊れ方が読みにくい

## 一度目の実装から引き継ぐ教訓

**① 透明な当たり判定の層と、見えている要素は別物**：PC版のカバーフローは、3D変形されて見えているカード本体（`.cf-item`）と、その位置にJSが追従させる透明な当たり判定（`#cfOpenHit`、`position: fixed`）の2つの層でできている。一度目は透明な層にタッチイベントを付けたため、実機でスワイプが反応しなかった。タッチやクリックを追加するときは「実際に指が触れる要素はどれか」を先に確かめる（`3D変形とスタッキングコンテキスト_仕様書.md`も参照）。

**② 「完全フラット化」は求められていなかった**：スマホで3D演出をアニメーションごと切ったところ、「カバーフローではなくなった」というフィードバックで撤回した経緯がある。奥行きと傾きだけ0にし、縮小・透明度・アニメーションは残す、という現在の方針はここから来ている。

**③ CSS Gridの列幅は、同じ列の全アイテムの中で一番大きい「縮められない幅」に引っ張られる**：一度目の実装で「スマホで画面の大半が黒くなる」不具合が長期化した。原因は`header.top`に`min-width: 0`がなく、ヘッダー内の日付表示（`white-space: nowrap`）の文字列幅が、1カラムの列全体の最小幅として採用されてしまったこと。同じ列にいたカバーフロー（`.left-col`）まで押し広げられ、16:9のカードが巨大化していた。

- Gridで要素が異常に大きくなったら、疑わしい要素1つだけでなく同じ列・同じ行を共有する全アイテムを横断的に確認する
- `white-space: nowrap`の動的テキスト（日付・時計など）は、親を押し広げる典型的な原因
- 原因不明の数値異常は、`console.log`を数か所に置いた二分探索で「どの処理の前後で値が変わるか」を追うと早い
- 「実害がないから」と原因不明のまま様子見した問題は、後で別の形で出てくる

**現行コードとの関係**：現在はスマホ版で`.header-date`を非表示にしているため、日付テキストが列幅を押し広げる経路そのものは断たれており、縦・横とも検証で問題は出ていない。ただし保険として`header.top`に`min-width: 0`を入れるかどうかは未決。

**④ 一度に積み重ねない**：変更は1つずつ、検証してから次へ進む。PC版の非回帰確認（要素の位置とサイズを変更前後で比較）は、スマホ側の変更のたびに行う。
