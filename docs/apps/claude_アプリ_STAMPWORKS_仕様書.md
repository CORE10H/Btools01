# アプリ：STAMPWORKS（`apps/stampworks.html`）LINEスタンプの企画と下ごしらえ 仕様書

## 概要

LINEスタンプの制作を手伝う先天的アプリ（`builtin`）。2026-10-10に新設。claude.ai のチャットで作って確かめた単体版（「スタンプ下ごしらえ」）を、SIDE-OPS に組み込んだもの。

- 名前：STAMPWORKS。ユーザーが候補（DIECUT・STAMPWORKS・STICKERLAB・スタンプ下ごしらえ）から選んだ
- ランチャー表示名：`STAMPWORKS`（`BUILTIN_APP_CHOICES`）。カバー画像は`apps/img/stampworks.jpg`（900×506。`D:\dev\sideops_sync_verify\cover_stampworks.dart`が`icon_src/stampworks.html`のキャンバスで描いて書き出したもの）
- 1ファイル（HTML＋CSS＋JS）。外部ライブラリなし（ZIPも自前で組み立てる）
- `<head>`で`sideops-theme-bridge.js`（テーマ・同期の印・戻るボタン）を読み込む
- 使う端末：PC（Windows・Edge）とスマホ（Xperia 5 II・Chrome／Brave）。スタンプメーカーはスマホのアプリなので、切り抜き・書き出しはスマホで使うことが多い想定

### 流れ（アプリが受け持つのは ①②④⑤）

1. **企画**：テーマ・キャラクターの見た目・絵柄・個数・セリフを決める（アプリ内）
2. **プロンプトを作る**：画像1枚ごとのプロンプトを合成し、コピーする（アプリ内）
3. **画像を生成する**：ChatGPT・Gemini などに貼って画像を作り、端末に保存する（アプリ外）
4. **切り抜く**：生成した画像を取り込み、背景を透明にし、1コマずつ切り分ける（アプリ内）
5. **書き出す**：LINEスタンプメーカー用・Creators Market用の形に整えて保存する（アプリ内）
6. **仕上げて申請する**：LINEスタンプメーカーで取り込み、文字などを足して販売申請する（アプリ外）

SCRIBITと同じく、③と⑥は人がアプリの外でやる。外部のAI APIは使わない。単体版にあった「AIでセリフ案を作る」（claude.ai の`window.claude`を使うボタン）は入れず、外部AIに貼る「セリフ案を頼むプロンプトをコピー」だけを残した。

### 単体版から移したもの・変えたもの

| 部分 | 扱い |

| プロンプトの合成（`PRESETS`・`STYLES`・`KEYS`・`PER`・`buildPrompts`・`phraseRequestPrompt`・`presetLines`・`parsePhrases`） | そのまま。読む先を「開いている企画」（`S.plan`）に変えた |
| 書き出し（`drawFit`・`buildOutputs`・`buildZip`・`crc32`・`shareAll`） | そのまま。保存の直前に、書き出す画像の作り直しを待つ（`readyOutputs`。選び直した直後に押しても古い画像を保存しない） |
| `saveFile` | `window.claude`（downloads）の分岐を消し、`<a download>`だけにした |

| 見た目（丸いフォント・型抜き風の見出し・`prefers-color-scheme`の分岐・説明文） | SIDE-OPS の見た目に置き換えた（下の「見た目」） |

## データ

### 企画（同期する）：IndexedDB `sideops_stampworks`・版1

ストア`plans`（`keyPath: 'id'`、索引なし）。1件＝スタンプ1セットの企画。

| 項目 | 型 | 内容 |
|---|---|---|
| `id` | string | `sw_`＋`yyyymmddHHMMSS`＋`_`＋乱数6文字（MANUSCRIPTの日時入りIDに倣う） |
| `title` | string | 企画名。空でもよい。一覧では、空ならテーマの先頭20文字、それも空なら「無題の企画」と出す |
| `status` | string | `idea`（企画中）・`making`（制作中）・`applied`（申請中）・`selling`（販売中） |
| `theme` / `character` | string | テーマ／キャラクターの見た目 |
| `style` / `styleCustom` | string | 絵柄：`yurukawa`・`pop`・`chibi`・`watercolor`・`gekiga`・`pixel`・`custom`。`custom`のときの文 |
| `count` | number | 8・16・24・32・40 |
| `per` | number | 1枚の画像に描く数：4・6・9 |
| `textMode` | string | `ai`（文字もAIに描かせる）・`none`（文字なし） |
| `key` | string | 背景色：`green`・`blue`・`magenta` |
| `preset` | string | セリフのプリセット：`daily`・`work`・`family`・`friends`・`react` |
| `phrases` | string | 1行に1つ「セリフ｜しぐさ」 |
| `phrasesEdited` | boolean | false の間は、個数・コマ数・プリセットを変えるとセリフをプリセットで入れ直す（単体版と同じ） |
| `memo` | string | 自由なメモ（申請の控えなど） |
| `createdAt` / `updatedAt` | number | 時刻 |

- 読み込むときは1件ずつ値を確かめ、知らない値は既定値にする（`normalizePlan`。ほかの端末の新しい版から届いた形でも落ちないように）。知らない項目は消さずに残す。セリフが空なら、プリセットで入れ直す（単体版と同じ）
- 自動保存：入力から600ms後に`put`。保存ボタンは置かない（メモ・SCRIBITと同じ）。画面に「編集中…」「保存しました」
- 保存待ちを今すぐ書き込むとき：一覧へ戻る・Stageを閉じる合図（`sideops:stage-closing`。`e.source === window.parent`を確かめる）・`pagehide`・`beforeunload`・裏に回ったとき（`visibilitychange`。スタンプメーカーへ切り替えたときなど）
- 別のタブとの食い違い：MINDFRAMEと同じく、保存の直前にDBの`updatedAt`を読み、自分が読み込んだ（最後に保存した）時点より新しければ、黙って上書きせずに「こちらで上書き／あちらの内容を読み込む」を聞く。閉じたら保存せず（「未保存（別の画面と食い違い）」）、次に入力したときにもう一度聞く
- `onupgradeneeded`で作るストアの形は、この版のまま変えない（同期は記録した形でほかの端末にDBを作る）
- 同期の対象（`js/sync.js`の`DB_RULES`に`sideops_stampworks`を追加）。第2弾で同じキャラクターの設定を使い回せるよう、PCとスマホで同じ企画を持つ

### 作業中の画像（同期しない）：IndexedDB `sideops_stampworks_work`・版1

| ストア | キー | 中身 |
|---|---|---|
| `sheets` | `id`（索引`planId`） | 取り込んだ画像1枚。`id`（`sh_`＋時刻＋乱数）・`planId`・`name`（ファイル名）・`blob`（取り込んだファイルそのもの）・`r`・`c`（コマ割り）・`split`（`auto`/`even`）・`order`・`addedAt`・`usedAt` |
| `session` | `planId` | 企画ごとの選択。`off`（使わないコマのIDの配列）・`mainId`（メイン画像のコマのID か null）・`updatedAt` |

- **同期しない**（`DB_RULES`に入れない）。数MBの画像を毎回送ると同期が重くなるため（2026-10-08に同期の重さを直したばかり）。画像はカメラロールに元があり、作り直せる。テーマブリッジはこのDBへの書き込みにも印を付けるが、同期は`DB_RULES`にないDBの印を数えない（`readDirtyMarks`）ので、未送信の扱いにはならない
- 一時保存する理由：スマホでは、戻るボタンでStageが閉じる・スタンプメーカーへ切り替えている間にブラウザが裏で閉じる、で切り抜きが消える。開き直したら続きからできるようにする
- 切り抜いた結果は保存しない。企画を開くたびに`blob`から`processSheet`で作り直す（透過の調整を変えれば作り直せるため）。開いた企画の`sheets`と`session`を読み、取り込み・コマ割り・選択（使わないコマ・メイン画像）まで戻す。読み込みの途中は「作業中の画像を読み込み中…（i/n）」を出し、その間は新しい取り込みを受け付けない（選択の記録を上書きしないように）
- 選択の記録は操作から400ms後に保存し、企画を閉じる・Stageを閉じる合図・画面を離れるときは今すぐ書き込む。開き直しの途中（まだ記録を読み終えていないとき）は書き込まない
- `usedAt`（使った時刻）は企画を開いたときに更新する。画像ごと書き直しになるので、1日に1回まで
- 歯止め：1企画あたり12枚まで、1ファイル20MBまで（超えたら取り込まず、理由を出す）
- 片付け：
  - 企画を消したら、その企画の画像と選択も消す
  - 編集の☰「この企画の作業中の画像を片付ける」・一覧の☰「作業中の画像をすべて片付ける」（どちらも確認あり。元の画像と企画の中身は消えない）
  - 開いたとき、なくなった企画（ほかの端末で消された企画）の画像と、30日使っていない画像（`usedAt`）を消す。企画を読めなかったときは、企画の有無では消さない（全部消してしまわないように）。画面に「この端末に一時保存し、開き直すと続きからできます（同期はしません）。30日使わないと自動で片付けます」と書いてある
- このDBを開けないとき（容量不足など）も、切り抜きと書き出しはできる（保存しないだけ。画面に一言出す）。保存に失敗したときも、トーストで1回知らせて作業は続けられる

### 端末ごとの設定（localStorage）

キー`sideops_stampworks_prefs`（LIBRARIUMの`sideops_librarium_prefs`と同じ置き方。同期しない）。読み書きはすべて`try`で囲む（使えなくても動く）。

- `lastPlanId`（最後に開いた企画。開いたら覚え、一覧へ戻ったら消す。覚えていれば、次に開いたときその企画から続ける）・`tab`（`p`/`c`/`s`）・`bg`（確認用の背景）・`out`（`maker`/`cm`）
- 透過の調整：`strength`（0〜100）・`holes`・`erode`（0/1/2）・`clean`。企画の中身ではなく、そのとき取り込んだ画像に合わせる調整なので端末ごと

## 画面

SCRIBIT・DONE MORE と同じ「1画面の中で切り替え」：**一覧 → 企画を選ぶ → 編集（3つのタブ）**。

### 上のバー（`.app-bar`）

- 一覧：左に`// STAMPWORKS`、右に［＋ 新しい企画］と☰（作業中の画像をすべて片付ける）
- 編集：左に［← 一覧］と企画名、右に☰（この企画を複製・この企画の作業中の画像を片付ける・この企画を削除）

### 一覧

- 企画のカード：企画名・状態・個数と1枚の数・更新日時・この端末にある作業中の画像の枚数。更新が新しい順
- 上に状態の絞り込み（すべて／企画中／制作中／申請中／販売中。それぞれの件数つき）
- 空のとき：「企画がありません」と［＋ 新しい企画］
- 企画のDBを開けないとき：「保存機能を使えません」と［＋ 保存せずに使う］（企画は画面の中だけ。閉じると消える。編集の画面にもその旨を出す）
- ［＋ 新しい企画］は二度押ししても1つだけ作る。新しい企画・複製した企画は「1 プロンプト」のタブから開く（最後に使ったタブではなく）

### 編集：1 プロンプト

先頭に「企画」（企画名・状態・メモ）。続けて単体版と同じ：テーマとキャラクター／絵柄と枚数（絵柄・セットの個数・1枚の画像に描く数・文字・背景色）／セリフ（プリセット・入れ直し・セリフ欄・セリフ案を頼むプロンプトをコピー）／生成AIに渡すプロンプト（1枚ごとのカードと［コピー］）。

### 編集：2 切り抜き

画像を読み込む（選ぶ・PCはドラッグや貼り付けでも）。画像ごとのカード（元画像の小さな絵・ファイル名・何コマ見つかったか・背景の色・コマ割りと切り方の選択・注意）。切り抜き結果のタイル（タップで使う・使わない）、確認用の背景（市松・白・黒・トーク）、全部使う／全部外す、うまく切れないときの調整（透過の強さ・囲まれた背景も消す・フチを削る・小さなゴミや区切り線を消す）。

- 落とし先の枠を外れて画像を落としても、画像が開いてアプリが入れ替わらないようにした（編集中なら取り込む）

### 編集：3 保存

書き出し先の切り替え、個数の表示、保存のボタン、書き出した画像（1枚ずつ［保存］）、スタンプメーカー／Creators Marketでの手順、申請前のチェック。

### 複製

［この企画を複製（第2弾を作る）］で、中身をすべて写した新しい企画を作る。企画名に「 2」を付け（企画名が空なら一覧に出る名前に付ける）、状態は企画中。作業中の画像は写さない。

### スマホの戻るボタン（SIDE-OPSのStageの中）

LIBRARIUMと同じ作り。`window.SideOpsBackLayers`に編集の画面（`#editView.is-active`）を足して、編集の画面も1段として数える。`window.SideOpsBack`は、確認が開いていなければ編集の画面を閉じて一覧に戻す。戻るボタンで「確認 → 編集の画面 → Stage」の順に閉じる（`core/claude_メインステージ_仕様書.md`「戻る操作」）。アプリの中で`history.pushState`・`location.hash`は使わない。

### 見た目（SIDE-OPS に合わせる）

- フォント：Rajdhani（見出し・数字）＋ IBM Plex Sans JP（本文）。`<link>`と`:root`の既定値は`apps/scribit.html`と同じ
- `prefers-color-scheme`の分岐は持たない（テーマブリッジが`color-scheme`も合わせる）。ボタンはSCRIBITの`.btn`・`.btn.primary`・`.btn.danger`の型（大きい操作は`.btn.lg`）
- 色の置き換え：下地`--bg`・面`--panel`／`--bg-alt`・文字`--text`／`--text-dim`・区切り`--line`／`--line-soft`・主なボタンと選んでいるもの`--cyan`（下地`--cyan-dim`）・消す`--magenta`・注意`--amber`（下地`--amber-dim`）・キーボードの焦点`--cyan`
- **テーマに追従させない色（わざと）**：確認用の背景（市松・白・黒・トーク）と市松の2色（`#FFFFFF`・`#DDE3EA`）。スタンプが実際に置かれる背景を真似て確かめるためなので、テーマで変えない。トークの`#8FAAD3`はLINEの既定のトーク背景に近い色（実測ではない）
- 幅320・360・375・768pxで、バー・タブ・ボタンがはみ出さない・重ならない（自動の確認あり）。書き出した画像は幅320pxでも2列に並ぶ

## 透過と切り分けの仕組み（単体版のまま）

プロンプトで背景を単色（グリーン等）に指定させ、画像の外周から背景色を推定し（中央値）、色の差（YCbCr）で透明にする。白・灰色の背景は色の距離で、外周とつながった部分だけを消す。もともと透明な画像はそのまま。輪郭の背景色かぶりを抜き（despill）、つながった絵のかたまりを数え、近くの部品（離れた文字・「！」）を1つのまとまりにしてマスに割り当てる。まとまりの数からコマ割りを推測する（1・4・9・16、6は縦長か横長か）。長い辺は2048pxまでに縮めて処理する。緑のキャラクターには、プロンプトの背景色をブルーかマゼンタにする（画面の背景色の選択で変えられる）。

## 書き出し

| 書き出し先 | 形 | ファイル名 |
|---|---|---|
| スタンプメーカー用 | 透明PNG 740×640（余白20px） | `stamp_01.png`〜 |
| Creators Market用 | 透明PNG 370×320（余白10px）＋`main.png` 240×240＋`tab.png` 96×74 をZIP | `01.png`〜 |

- 保存の方法：1枚ずつ（各画像の［保存］）・ZIP（無圧縮）・まとめて写真に保存（`navigator.share`で`canShare`がtrueのときだけ出す。単体版と同じ）
- **［全部ダウンロード］**（スタンプメーカー用だけ）：PNGを1枚ずつ順に、400msの間を空けてダウンロードする。途中で止める［止める］ボタン（別のボタン。押し間違えて止めないように）。終わると枚数と「足りないときは、ブラウザの『複数のファイルのダウンロード』が許可されているか確かめてください」を出す。AndroidではZIPをスタンプメーカーで開けず、1枚ずつ押すのは手間が多いため。企画を閉じる・書き出し先を切り替えると止める
- iframe の中からのダウンロード：本体と同じオリジン（GitHub Pages）なので`<a download>`が効く想定（要実機確認）
- Creators Market の規格（スタンプ最大370×320・メイン240×240・タブ96×74・PNG・背景透過・余白10px程度・1ファイル1MB以下）は第三者の記事（2026-06-28確認と書かれたもの）による。画面にも「申請の前に、公式の制作ガイドラインで確かめてください」と書いてある

## 誤作動を防ぐ歯止め

| 場面 | 歯止め |
|---|---|
| 企画を消す | 確認（`.confirm-overlay`）。「元に戻せません。この端末の作業中の画像n枚も消えます（ほかの端末の画像は、その端末で開いたときに片付きます）」。消す前に保存待ちを捨てる（消した企画を書き戻さないように） |
| 入力の直後にStageを閉じる・戻るボタン・裏に回る | 600msの自動保存＋閉じる合図・`pagehide`・`visibilitychange`で即時に保存。選択の記録も同じ |
| 保存の失敗 | トーストで知らせる。1件の失敗で画面全体を止めない |
| 企画のDBを開けない | 一覧に「保存機能を使えません」。保存せずに使うこともできる |
| 作業中の画像のDBを開けない・保存できない | 切り抜きと書き出しはそのまま使える。画面に一言 |
| 画像の取り込み | 画像以外・20MB超・12枚超・読めない画像は、1枚ずつ理由を出して飛ばし、残りは続ける（「取り込まなかった画像（n件）」の一覧） |
| 背景が白・灰の画像、ムラのある背景、見つからないコマ | 単体版の注意（そのまま） |
| Creators Market用のZIPで、個数が8・16・24・32・40以外、または40超 | 書き出す前に確認を出す（単体版は表示だけだった） |
| メイン画像を選んでいない | 先頭のコマを使う（単体版と同じ）。そのことを画面に書いた |
| 選び直した直後に保存を押す | 書き出す画像の作り直しを待ってから保存する（古い画像を保存しない） |
| 開き直しの途中に取り込む・選ぶ | 取り込みは読み込みが終わるまで受け付けない。選択の記録は読み込みが終わるまで書かない |
| 同期で企画が2つずつになる | 起きない（作るたびに別のID。名前が同じでも別の企画）。まとめる処理は入れない |
| 2つのタブで同じ企画を書き換える | 保存の直前に`updatedAt`を確かめ、どちらを残すか聞く（MINDFRAMEの型） |
| 企画を消した直後の片付けの取りこぼし | 開いたときに、なくなった企画の画像を消す |
