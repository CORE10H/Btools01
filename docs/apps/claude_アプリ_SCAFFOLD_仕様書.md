# アプリ：SCAFFOLD（`apps/scaffold.html`）AIのべりすと執筆支援ツール 仕様書

## 概要

「AIのべりすと」（日本語小説生成AI）向けの執筆準備を支援する、クリップボード・ブリッジ型のツール。SCRIBIT（`アプリ_SCRIBIT_仕様書.md`）と同様、アプリ自体は外部LLMのAPIを呼び出さず、プロンプト生成と、外部LLMの出力をAIのべりすとの各入力欄向けに分別・整形する処理に徹する（静的HTMLで完結させる方針）。IndexedDB本実装済み（DB名`sideops_scaffold`）。テーマブリッジ（`sideops-theme-bridge.js`）にも接続済み。

元々は別プロジェクトで単独開発されていたが、SIDE-OPS本体へ統合する方針に変更。統合にあたり旧UIモック（原稿用紙×赤ペン添削デザイン）は撤回し、一からデザイン・仕様を設計し直した。

### SCRIBITとの違い（統合しない理由）

SCRIBITは①②④のみ（LLM出力を人間がそのまま利用する前提で、パース処理を持たない）。SCAFFOLDは③として「LLM出力を固定見出し規則で解析し、AIのべりすとの複数の入力欄に機械的に分別する」工程を必須で持つ点が本質的に異なる。この違いにより、カード一覧の入口だけ共有しフォーマットごとに中身を切り替える統合案は検討したが、パースの有無で必要な工程数・データ構造が変わり複雑化するため見送り、独立アプリとして維持する方針で確定した（他の生成AIサービス向けにパース機構を横展開したくなった場合は、アプリ統合ではなくパースロジック部分の汎用化＝見出し名・区切り記法の設定可能化で対応する）。

## 4フェーズ構成

1. **①骨子を書く**（アプリ内）：主人公・目標・舞台・ジャンル・現状/対立・視点・脇役等を、自由記述の1つのテキストエリアにラフに書く（項目分けはしない。「本当に簡単なメモ」の位置づけ）
2. **②プロンプトを合成する**（アプリ内）：テンプレートを選び「合成する」を押すと、①を実用段階まで引き上げるよう外部LLMに依頼する完成プロンプトを生成。コピーボタン付き（クリップボードAPI失敗時は`execCommand('copy')`にフォールバック、失敗しても画面は壊さず握りつぶす）
3. **③AIのべりすと形式に分別する**（アプリ内）：外部LLMの出力を貼り付けると、脚注・メモリ・キャラクターブック・禁止ワード・備考の各欄向けに自動分別して表示
4. **④清書を貼り付ける**（アプリ内）：AIのべりすとで実際に生成した本文を貼り付け、公開前の手直しをアプリ内で直接編集する

SCRIBITの③（外部AI生成）・⑤（LLMのプロジェクトナレッジへの格納）に相当する工程は、SCAFFOLDでも同様に人力・アプリ外のフローとする。

## データ構造（1下書きあたり、IndexedDB本実装・DB名`sideops_scaffold`）

- タイトル（任意、未入力時は「（無題の下書き）」表示。編集は即時保存＝デバウンス不要な軽量データとして扱う）
- カバー画像（任意、16:9・**Base64（データURL）で保存**。`image/*`のみ許可、5MB上限のバリデーション。設計段階ではBlob方式との比較で持ち越しだったが、下書き自体が軽量データのためBase64を採用して確定）
- ①骨子本文
- ②生成済みプロンプト（テンプレートID・合成結果）
- ③LLM出力の貼付テキスト、およびパース結果
- ④清書本文
- 進捗ステータス（後述）
- 更新日時

保存先ストアは`entries`（下書き本体）・`templates`（プロンプトテンプレート）の2ストア構成。`IndexedDB実装パターン_仕様書.md`の定型パターンに準拠。メモリ上に`drafts`/`templates`のキャッシュ配列を持ち、DBを唯一の正として都度反映する設計。

### テンプレート（②）

- 名前＋固定文面＋差し込み位置`{{骨子}}`を1箇所含む。複数登録可（SCRIBITと同型）
- テンプレート本文に`{{骨子}}`が無いと保存できない（SCRIBITと同じフールプルーフ）
- 最後の1件のテンプレートは削除不可（新規作成中は削除ボタン自体を非表示にする）
- 初回起動時のみ初期テンプレートを1件自動投入する（「最後の1件は削除不可」の起点を必ず用意するため）
- **固定フォーマット指定ブロックはテンプレート本文と分離**（詳細は次節）
- **テンプレート削除時の下書きへの影響（案A、確定）**：使用中の下書きが存在する場合、削除確認ダイアログに使用件数を明記した上で警告する。削除を実行すると、それらの下書きの`templateId`は`null`に戻る（下書き自体は削除されず、テンプレート未選択の状態になり選び直しが必要）

## 保存先

（データ構造節に記載の通り）IndexedDB（DB名`sideops_scaffold`）。`entries`（下書き本体）・`templates`（プロンプトテンプレート）の2ストア構成。

## 進捗ステータス

自動判定の4段階＋独立した手動フラグ「完了」で構成する（後戻り可能）。

| 状態 | 条件 | 判定方法 |
|---|---|---|
| ①下書き中 | 骨子入力のみ | 自動 |
| ②生成待ち | ②のプロンプトを生成・コピー済み | 自動 |
| ③分別済み | ③のパース・分別表示まで到達 | 自動 |
| ④推敲中 | ④に清書本文を貼り付け済み（1文字以上） | 自動 |
| **完了** | ユーザーが「完了にする」ボタンを押した | **手動**（別軸のフラグ） |

- 自動4段階は`stage < N`判定のみで前進させ、後退はしない（既に④まで進んだ下書きの①〜③を再編集しても勝手に後退しない）
- ④の清書本文を空にしても③へは自動で後退しない（誤操作で進捗表示が消えるのを防ぐフールプルーフ）
- 「完了」は独立フラグのため、④推敲中のまま何度でも編集を続けられ、ユーザー自身が公開判断を下したタイミングでのみ確定する。誤操作防止のため「完了を取り消す」ボタンも用意し、一方通行にしない

## 画面構成

SCRIBIT・DONE MOREと同じ「1画面内タブ切替え」方式（一覧→クリックで編集画面）。

### 一覧画面

- 縦1列（作品カード形式）。各カード左に16:9のカバーサムネイル（未設定時はプレースホルダーアイコン表示）
- 表示情報：タイトル・進捗ステータスのピル表示（完了時は塗りつぶし強調）・更新日時。更新日時の新しい順に並べる
- タイトルでの検索、「＋新規下書き」ボタン

### 編集画面

- ヘッダー：カバー画像アップロード欄（16:9、クリックでファイル選択、設定済みなら✕で削除）・タイトル入力・削除ボタン
- フェーズトラック（①〜④の進捗タブ表示、現在地と完了済みフェーズを視覚的に区別）
- ①〜④の各ブロックを縦に並べる構成
- 「一覧へ戻る」操作時は、デバウンス待機中の変更を即座にflushしてから遷移する（変更の取りこぼし防止）

## ①骨子入力の実装詳細

- 自由記述の1つの`<textarea>`
- メモアプリと同じデバウンス自動保存（600ms、保存ボタンなし）。以下のフールプルーフを踏襲：
  - 保存処理のPromiseチェーン直列化（連続入力の多重実行防止）
  - タイトル・骨子・清書のすべてが空の下書きは、閉じる際にゴミデータとして自動削除する（カバー画像やプロンプト合成・パース結果だけがある状態は「空」とはみなさない＝ユーザーが何らかの作業をした形跡があるものは残す、というメモアプリより一段階丁寧な判定）
  - 閉じる操作時の即時flush
  - `beforeunload`での保存待ち警告

## ②プロンプト生成の実装詳細：フォーマット指定の分離（B案で確定）

③のパース処理は`## FOOTNOTE`等の固定見出しに依存する契約（インターフェース）であり、ユーザーがテンプレートを自由編集しているうちに見出し表記を意図せず壊すリスクがある。これを防ぐため、**フォーマット指定ブロックはテンプレート本文と分離した固定ブロックとしてアプリにハードコードし、ユーザーは編集できない**方式（B案）で確定した。

```
[ユーザーが編集するテンプレート本文（{{骨子}}を含む）]
　　　　　　　＋（結合、非表示）
[固定のフォーマット指定ブロック（アプリにハードコード、編集不可）]
　　　　　　　↓
[完成プロンプト（コピー対象）]
```

「合成する」押下時、テンプレート本文の`{{骨子}}`に①の内容を差し込んだ後、末尾に固定フォーマット指定ブロックを自動連結して完成プロンプトを生成する。ユーザーが編集画面で見るのはテンプレート本文のみ。

### 固定フォーマット指定ブロックの内容（実装確定版）

外部LLMに対し、以下の見出し構成のMarkdownで出力するよう指示する（`FORMAT_INSTRUCTION_BLOCK`としてハードコード）：

```
---
【出力フォーマット指定（厳守）】
以下の見出し構成のMarkdownで出力してください。見出し文字列は改変しないでください。
## FOOTNOTE
（脚注に入れる内容）
## MEMORY
（メモリに入れる内容）
## CHARACTERBOOK
（キャラクターが複数いる場合は次の形式で区切って列挙。1人もいない場合はこのセクション自体を省略可）
TAG: キャラクター名
（説明文）
@priority 3
---
TAG: 次のキャラクター名
（説明文）
## BANWORDS
（禁止したい単語。改行区切りで列挙）
## NOTES
（上記に入らない補足があれば自由に記述。無ければ「特になし」）
```

## ③パース処理の実装詳細

### セクション分割

`^## セクション名$`（行頭・行末で完結する見出し行）を正規表現で検出し、認識対象は`FOOTNOTE`/`MEMORY`/`CHARACTERBOOK`/`BANWORDS`/`NOTES`の5つのみ（画面表示ラベルはそれぞれ「脚注」「メモリ」「キャラクターブック」「禁止ワード」「備考（アプリ外メモ）」）。見出しが1つも検出できない場合は、警告文言を表示した上で原文をそのまま1件表示するフォールバックに倒す（パース失敗でアプリが機能停止しない設計）。未知の見出しはスキップする（無視するだけで落とさない）。

### CHARACTERBOOK：区切り規則（案B、Claude推奨で確定）

複数キャラクターを扱うため、以下の区切り線＋ラベル方式を採用：

```
## CHARACTERBOOK
TAG: 太郎
[説明文...]
@priority 3
---
TAG: 花子
[説明文...]
```

- `---`（行頭、前後空白許容）でブロックを分割
- 各ブロックから`TAG:`行を正規表現で抽出し、タグ名として扱う
- `TAG:`行が見つからないブロックは「タグ未検出」として警告付きでそのまま1件表示するフォールバック（アプリを落とさない）
- `@`で始まるコマンド行は`@priority`/`@range`/`@and`/`@not`/`@random`/`@addbanword`/`@addbias`のみ許可（AIのべりすと本体の1行1コマンド制約を踏襲）。不明なコマンドは無視して警告表示

検討した他案：案A（Markdown見出し`### タグ名`方式、可読性は高いがキャラ名に`#`等が混じると崩れやすい）、案C（JSON半構造化、パースは正確だがLLMの自由出力での崩れリスクが高く可読性も低下）。堅牢性重視の方針から案Bを採用した。

### BANWORDS：整形方針（正規化を採用）

AIのべりすと側は改行・`<<|>>`のどちらの区切りも受け付けるため、パース処理自体に必須の変換ではない。ただし人間側の使い勝手（目視編集のしやすさ、件数把握）を優先し、**1行1語に正規化**する方針で確定：

- 改行・`<<|>>`の両方を区切り文字として認識
- 空白トリム、空行除去、重複除去
- 件数表示（「◯件」）
- コピーボタンで1行1語形式のままコピー欄へ

### FOOTNOTE・MEMORY・NOTES

単一テキストブロックとして扱う（`## 見出し`の次行から次の`## `見出し手前まで）。コピーボタン付き、内容が空の場合はボタンを非活性化。NOTESは「アプリ外メモ」の位置づけで、コピー対象外でもよいが一応表示する。

## ④清書貼り付けの実装詳細

- AIのべりすとで実際に生成した本文を貼り付ける`<textarea>`
- **編集可能**（公開前の手直し用途）。①と同じデバウンス自動保存方式
- ファイルダウンロード等は行わない（アプリ内保存のみ、SCRIBITの④＝mdファイル変換とは異なる）
- 文字数カウントを表示

## テンプレート管理画面の実装詳細

ハンバーガーメニュー等から開く専用モーダル（一覧⇔編集の2ビュー切替）。

- **一覧ビュー**：テンプレート名＋本文プレビュー（省略表示）をリスト表示。クリックで編集ビューへ。「＋新規テンプレート」ボタン
- **編集ビュー**：名前入力欄・本文`<textarea>`（`{{骨子}}`必須バリデーション、未検出時はエラー表示）・保存/キャンセル/削除ボタン
- **削除確認**：使用中の下書きがある場合「このテンプレートを削除しますか？現在このテンプレートを使用している下書きが◯件あります。削除すると、それらの下書きはテンプレート未選択の状態に戻ります（下書き自体は削除されません）。」と明記。無い場合は「このテンプレートを削除しますか？」のみ

## カバー画像

- 一覧・編集画面ともに**16:9アスペクト比**で統一（SIDE-OPS本体のカバーフロー・Discoticaと同基準）
- 任意設定。未設定時は一覧でプレースホルダーアイコン表示
- 画像形式（`image/*`）・サイズ上限5MBのバリデーション（他アプリと同じフールプルーフ方針）
- **保存方式はBase64（データURL）で確定**。下書き自体が軽量データのため、プロンプトギャラリー等のBlob方式ほど厳密でなくてもよいと判断した

## 削除確認（下書き）

「この下書きを削除しますか？この操作は取り消せません。」の簡易モーダルを経由する。

## テーマブリッジ接続

`apps/sideops-theme-bridge.js`を読み込み、本体テーマに追従済み（`テーマブリッジ_仕様書.md`の許可リスト変数名に準拠）。
